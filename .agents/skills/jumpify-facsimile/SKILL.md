# Jumpify Facsimile

Create a facsimile Format 1 conversion in ignored scratch space. Preserve measured source panels while keeping costs, controls, Tags, grants, and Tracker behavior live.

## Workflow

Before authoring, classify what each clause does, not merely which nouns it contains. Give every prose and Choice entry one `grantInventory.entryDecisions` record with a nonempty `clauses` array. Give each semantically distinct clause its own exact `sourceEvidence`, `semanticForce`, dispositions, reason, and any resulting grant keys; never assign one force to a mixed paragraph. A paragraph may therefore contain separate retained-existing, narrative, explicit-grant, and current-Jump-rule clauses without turning every mentioned noun into a grant. Only an explicit-grant or current-Jump-rule clause may own unconditional `grantKeys`. Add exactly one `choiceGrantSemantics` record per authored Choice grant and resolve ambiguous cross-entry people, creatures, objects, and forms in `referentResolutions`. Quote the actual ambiguous mention plus enough contiguous context to establish its relationship; another occurrence of the same noun elsewhere in the entry is not evidence for the resolution. Verify every same/new target against the canonical Choice and the grant actually created by that Choice. Distinguish explicit new grants, permission to retain something already owned, narrative setup, current-Jump rules, conditional effects, and mechanical instructions. For Choice grants, distinguish entity acquisition, entity classification, entity enhancement, ability, possession, form, circumstance, identity property, and resource change; match the Format 1 grant kind to that contextual role. A category, tier, rarity, origin, or similar label may be a Property when it describes what an entity is, but may be a Perk when its actual effect grants a durable capability. Decide from the source meaning, not the label.

Build a source-wide entity-continuity table before creating any Companion, Form, or other entity grant. Compare every narrative or Choice-introduced entity with every later dynamic entity of the same kind. If mutually exclusive backgrounds or origins each explain how the Jumper meets, inherits, rescues, raises, or travels with one entity in the same functional role and a later singular Section asks the Jumper to name, select, or classify that role, treat the earlier prose as the origin of the later entity. Record `same-entity` resolutions targeting the one later dynamic grant and create no background-specific duplicate grants. Chronology alone (for example, calling something "pre-Starter" or "pre-companion") and verbs such as joins, follows, tags along, is rescued, or is taken along never prove a second entity. Use `new-entity` only when exact `distinctnessEvidence` establishes explicit additionality, an independent slot/count, simultaneous possession, or an incompatible source identity; record that category in `distinctnessBasis` and list every same-kind dynamic candidate as an exact `choiceHandle:grantHandle` value in `comparedDynamicEntityRefs`. Judge the complete source clause rather than an English keyword. Target Choice-owned grants by canonical Choice/grant handle and prose/Jump-owned grants by exact indexed `targetJumpGrantRef`. The validator derives every competing Companion/Form grant from canonical JDEF, so omitting a continuity record cannot hide it. If the source does not prove additionality, default to continuity. Include these relationships in the reverse-reference pass and verify the combined earlier-choice-plus-later-definition state produces one Tracker record.

For every dynamic Companion or Form, explicitly inventory `classificationChoiceHandles`, using an empty array only when the source has no mutually exclusive Choices that classify that entity. Keep the scalar name/species/identity owner separate and direct. When classification Choices exist, place their complete set—no omissions or unrelated members—in the one single-select Source named by `classificationSourceHandle`; none of those classification Choices may own or repeat the scalar input. Every member grants one shared stable Property with its own explicit source-authored classification value, and `classificationPropertyHandle` identifies it. Interpolate the selected value into the Tracker entity name and verify it there. A grantless classification selector, an omitted Property value that copies a boolean toggle, or a fixed generic role label loses the selected meaning. If a similarly named Choice only grants an enhancement or ability, keep it as a targeted Perk instead and do not list it as a classification Choice. When one Choice both classifies the entity and explicitly enhances it, author both grants and give each its own contextual semantic record; do not discard either effect to force the Choice into one category.

Give every visible Perk, Item, Companion, Form, and Trait grant between one and five concrete effect Tags. Give each taggable Choice between one and five as appropriate. Choose the count from independent useful filtering dimensions, record the rationale, and reject a substantial conversion where every Choice or grant mechanically receives exactly one Tag. When every affected entry genuinely has only one useful filtering dimension, record `tagCardinalityReview` with `status: justified`, the exact complete `choiceHandles` and owner/index-qualified `grantRefs` sets under review, and a source/effect-specific reason; this is the only exception and must not hide omitted, duplicate-named, or padded Tags. Never pad to a quota with section, cost, or redundant grant-kind labels.

Treat partial artwork like partial glyphs. When `edgeOwnership` says an edge is outside or clear of content, the crop audit must show a clean structural edge; foreground pixels touching that boundary mean the crop is clipped even if the intended object remains recognizable. A uniformly colored boundary is only a measurement candidate, not proof of ownership: reject a foreign rule, stripe, neighboring border, or partial solid artwork even when the edge is 100% uniform. `edgeOwnership` never authorizes partial content: an edge that deliberately owns foreground must identify a complete authored border, complete artwork edge, or unavoidable source-page boundary, not a glyph or object cut by the crop.

Regenerate crop assets and schema-version-2 `crop-audit.json` after every ledger rectangle, page, output, package flag, alt-text, source, or crop-tool change. Crop evidence is exact-input evidence: its source hash and every interior/four-edge metric must be present, and stale or stripped measurements cannot accept a later asset.

1. Resolve the supplied source path. Accept one PDF, one PNG/JPEG, or a directory containing only naturally ordered PNG/JPEG pages.
2. From the repository root, run:

   ```sh
   node .agents/jumpify/scripts/prepare-workspace.mjs <source> facsimile
   node .agents/jumpify/scripts/render-source.mjs <workspace>
   ```

   A schema-version-3 workspace cannot be resumed under this contract. Start a fresh numbered workspace from the source; clause decisions, crop evidence, interaction evidence, and independent review cannot be safely inferred or auto-migrated.

3. Read `extracted/pages/pages.json`, state the total source-page count, and inspect every rendered page before authoring. Populate every scaffolded `sourcePages` record and add the complete output `sections` inventory, including an explicit parent/child `surfaceTree` for each Section. Each source page must have verified entries, at least one packaged panel, and a reciprocal Section mapping.
4. Populate `ledger.json` with verified transcription, mechanics, measured panel rectangles, edge ownership, palette samples, comparisons, action-rail placement, and acceptance records. Complete every `interactionContracts` record before JDEF: choose the native Format 1 construct, direct-versus-Source placement, pricing policy, required states, and geometry policy. Complete `facsimileContracts` as well: one semantic-name, exact contiguous source-effect transcription, matching live-description, and Tag-placement decision per Choice; exactly one source-specific `grantInventory.entryDecisions` record with one or more clause decisions per prose and Choice entry; the exact subset producing unconditional grants in `sourceEntryIds`; every durable possession and current-Jump Trait circumstance as its own source-derived grant; every dynamic entity and its owned upgrades; and measured alignment relationships. Every `jump-grant` clause enumerates its complete `kind:Visible Name` `grantKeys`; no entry-level bucket may blur explicit grants with retained, narrative, or instructional clauses. Split illustrated kits into one entry per independently labeled object when possible and reconcile source, keys, canonical grants, and clean-baseline Inventory counts. The grant sweep explicitly considers duration, stopped home time, retained memory and moral/cognitive carryover, shared background rules, world/environmental circumstances, population and travel assumptions, authority responses, and local restrictions as Trait candidates. A `shared-choice-grant` clause must quote the exact shared effect and enumerate every target Choice; the gate verifies each target's live Trait description. A shared introduction effect inherited by multiple Choices is not preserved by copying only each card's individual prose. Build a reverse-reference index across all pages for later “free for,” discount, prerequisite, conflict, and override text that affects earlier Choices. Do not begin JDEF after inventorying only a sample or representative page.
5. Crop deliberate panels and sample colors:

   ```sh
   node .agents/jumpify/scripts/crop-assets.mjs <workspace>
   node .agents/jumpify/scripts/sample-colors.mjs <workspace>
   ```

6. Inspect all four edges and the complete interior of every crop. Remove neighboring gutters, borders, rules, and partial glyphs. Prefer one intact panel. When direct 390px comparison proves its text unreadable, record `panelStrategy: measured-fragments`, at least two contained packaged panel assets, and the measured reason; render every declared fragment and preserve their source relationships. A title-only fragment contains the complete title and nothing else; any prose it excludes remains in another measured source fragment rather than retyped system-font text. If title and prose cannot be separated without cutting content, retain the intact source panel. Measure and compare repeated siblings' content insets: right-column cards begin after the shared gutter and must not retain extra leading gutter pixels that become visible when stacked. Give every source Choice entry its own matching measured panel or explicit measured decomposition; never replace independent cards with one collection image and duplicate live expansions beneath it. Do not use arbitrary whole-page images where independent panels are required. Never split a shared heading, sentence, rule, band, or word between sibling crops: place shared content in one parent crop, then crop each child below or inside that boundary. Re-read rasterized text in rendered order at 720px and 390px so a desktop seam cannot hide separated sentence fragments.
7. Write editable `project/jump.jdef`, `project/choices.jdef`, and `project/layout.jdef`. Render each Choice's intact measured `source_panel`; do not substitute a title fragment plus retyped body copy merely to make a narrow layout taller or easier to read. Retain complete verified live descriptions, costs, Tags, grants, discounts, ownership, limits, option domains, selections, and controls beneath the visual panels; raster text is not a semantic substitute, but complete live descriptions need not be painted a second time. Every text-bearing header, instruction, transition, or outcome image that has no equivalent live text receives exact full visible wording in its alt text—summary alt text is insufficient. Every visible perk, item, form, companion, and Trait grant receives a live description preserving its source effect. Normalize semantic names independently from display pixels: source `SHINY` normally becomes Choice/perk `Shiny`, while source spelling remains authoritative unless the Developer explicitly authorizes a recorded normalization. Put every unconditional durable possession in a direct Jump-level Item grant. Give an entered entity a contextual visible name such as `"{{species}} (Starter)"`; do not encode that role as a generic perk. Do not invent caps or options, abbreviate effects, model spendable currency as an Item, or omit source overrides. Use direct Choice associations for standalone scalar controls; never place a scalar Choice in a Source merely to obtain an activation checkbox or radio. For every roll-or-pay Source, audit every exceptional member—not just one representative paid member—so a nested Free Pick or other naturally free-looking result still pays the source's manual-choice price and becomes free only through the roll resolution.
8. Compose compact additive Control/Tags/Cost rails in measured unused space. Put applicable live Tags in the available middle rail space, normally between Control and Cost. Treat the panel and rail as one bounded card: align their outer edges, continue the source accent frame around both, and keep the rail from dissolving into the Section background. Keep the narrow rail intrinsically sized around its live-element union; reject mostly empty rails taller than their source panels. Start with direct Control, Tags, and Cost children in one `wrap`; do not put an individual slot in a nested Stack or Inline merely to push it to an edge, because a container child can claim a minimum wrap track and force an otherwise fitting rail onto another row. Use the parent `justify` and child alignment first, then add a container only when measured evidence requires grouping. For a simple control plus Cost, start with opposite-edge placement and change it only when the source demonstrates another relationship. Do not cluster both actions at the start while leaving an unused opposite edge. For every repeated source Grid or Wrap, retain the greatest source-authored track count that actually fits at each required width; directly test two tracks at 720px before accepting a one-column fallback. If wide raster panels make a valid Wrap collapse despite fitting measured minimums, preserve a minimal valid Wrap experiment and a valid Grid experiment; do not apply `grow` because current Format 1 permits it only under Stack or Inline. Record a responsive-authoring gap when the valid alternatives cannot express the fitting track count. Make adornment and alignment decisions locally; never append generic full-width bars or generic breakpoints by habit.
   Never use compact Cost density for a repeatable Choice that can receive a discount: its resolved total must remain visibly readable with the base per-unit value in same-state evidence.
9. Build only through the application validator:

   ```sh
   corepack pnpm exec tsx .agents/jumpify/scripts/build-and-inspect.ts <workspace>
   ```

10. Start the application preview, then capture the imported archive through the real Tracker path:

```sh
corepack pnpm exec tsx .agents/jumpify/scripts/capture-and-audit.ts <workspace> http://127.0.0.1:4173
node .agents/jumpify/scripts/make-comparison-sheet.mjs <workspace>
```

11. Compare every panel with its source rectangle at the primary width, then inspect 720px and 390px behavior. For each source row, column, shared edge, center, or equal dimension, record corresponding 1440px rendered bounds in a separate `alignmentRelationships` record. The declared machine-readable relation must pass; a source row rendered as a stack or a panel that is merely nearby does not pass. Iterate until every acceptance record passes or a demonstrated gap remains.
12. Exercise rolled/manual pricing, continuity, limits, repeated ranks, discounts, locks, grants, Traits, companions, dynamic names, and controls. Capture every state required by `interactionContracts`. A text Choice's manual observation must contain a nonempty typed value different from its unset value; a filename or `actionSucceeded` flag alone is not typed-value evidence. For each dynamic entity, separately capture the populated creation control, its contextual visible name in the Companions or Forms Tracker tab, and an owned upgrade under that same record when upgrades exist; a control screenshot proves none of the Tracker projections. Companion upgrades use Companion ownership and Form upgrades use Form ownership; both must resolve beneath the same stable Tracker record. For cross-choice discounts or free entitlements, show the granting Choice active and the affected downstream Cost, balance, resource, or Tracker record in the same state. For repeated quantities, verify the resolved total cost/resource effect and Tracker quantity rather than only the rank input or per-unit badge. Open Inventory and verify every unconditional grant and description. Isolate unrelated contracts or clear each tested purchase after capturing it so cumulative spending cannot prevent later controls from activating; establish the prerequisite state needed by the contract under test. In the same Playwright run, assert the requested value and visible price, then write the DOM observation with control kind/value, activation layers, resolved costs, Section-relative surface/rail/neighbor bounds, and overlaps. Never use a fallback action without asserting its postcondition; differently named screenshots do not prove different states. Compare the numeric geometry and tightly cropped screenshots before and after each interaction. Reuse the readiness sequence established by `capture-and-audit.ts`; never convert a first-launch race, insufficient-balance refusal, or inferred state into a passing ledger record. Home, Stay, and Next-Jump outcomes are a deliberate exception to ordinary source-choice modeling: preserve them as prose and visuals only, with exact full alt text when rasterized, and do not create a Choice, Source, control, selection state, property, or outcome projection. A reviewer must treat the absence of Future controls as a required pass condition, not a semantic omission. After the final evidence or ledger edit, rerun `make-comparison-sheet.mjs` so `review-evidence.json` is a current exact projection before independent review.
13. Run a clean-context independent review after all source/render sheets exist. First audit every `verification/experiments/*-report.json`: its shipped/selected definition and evidence must describe the current JDEF and current captures; move superseded reports under `verification/rejected/` instead of exposing contradictory conclusions as authoritative evidence. Give the reviewer the source, every required Section capture at all three comparison widths, comparison sheets, editable JDEF, `verification/package-review.json`, the generated `verification/review-evidence.json`, the visual checklist, and the current raw reports under `verification/experiments/`—but no ledger, prior verdicts, rejected evidence, or expected defects. Experiments are evidence only for limitations the reviewer independently observes; they do not disclose or establish acceptance. The factual review manifest exposes every recorded interaction state, numeric DOM observation, referent resolution, and entity evidence path without exposing the converter's conclusions. Require the reviewer to return an explicit supported/unsupported adjudication for every `new-entity` resolution after comparing its quoted evidence, structured basis, exact target, and every same-kind dynamic candidate against the source; a declared basis is not proof. Map those exact adjudications into `independentReview.entityContinuityReviews`. Preserve the reviewer's raw report, record every finding under `facsimileContracts.independentReview`, resolve and recapture every open issue, and rerun the reviewer. The converter cannot certify its own independent review.
14. Require the completed ledger before handoff:

```sh
node .agents/jumpify/scripts/validate-ledger.mjs <workspace> --complete
```

## Hard stops

Do not finish while any of these remain:

- Unverified source content or mechanics.
- Source display capitalization used as ordinary semantic Choice or grant names.
- An incomplete source-wide grant inventory, an unconditional possession left only in prose/pixels, or a claim control for an automatic grant.
- A grant inferred from a mentioned noun without clause-level source-evidenced semantic force; one force assigned to a mixed paragraph; a jump-grant key owned by anything other than its explicit-grant or current-Jump-rule clause; retained-existing or narrative wording treated as a new grant; an unresolved or canonically unverified repeated entity mention; or a contextual semantic role that does not match the authored grant kind.
- An illustrated kit whose source labels, quantities, `grantKeys`, canonical Jump grants, and clean-baseline Inventory records do not reconcile one-for-one.
- An unconditional current-Jump duration, continuity, memory, background, environmental condition, or local restriction left only in prose/pixels instead of reviewed as a Jump-level Trait candidate.
- A context-free dynamic companion/form name, a role encoded as a generic perk, or an upgrade that does not target the stable entity.
- A dynamic entity whose classification inventory is omitted; a scalar identity owner embedded in a classification Choice; a classification set that is not exactly the complete membership of its one named single-select Source; a classification Property with no explicit source-authored value; or a selected classification absent from the entity's Tracker name.
- A live Choice description that paraphrases, shortens, reorders, or omits words from its exact reviewed source-effect transcription; an invented limit or option domain; a source discount/grant/override silently omitted; or spendable currency modeled as an Item.
- A Choice without a Tag-placement decision, applicable Tags omitted from their live slot, or placed Tags missing from the declared additive rail.
- A visible grant without one to five concrete effect Tags, a placed Choice with more than five Tags, missing Tag-count rationale, or a substantial conversion whose Tag counts are uniformly one without a `tagCardinalityReview` that exactly inventories and specifically justifies every affected Choice and grant.
- A Choice whose only Tags merely repeat its Section, cost class, or grant kind instead of describing a concrete effect.
- An unmeasured or failed alignment relationship between source blocks that visibly share an edge, center, baseline, or gap.
- Crop-edge contamination—including a foreign uniform stripe incorrectly accepted as a structural edge—distorted panels, poor contrast, detached controls, duplicate cost meaning, or arbitrary full-page rasterization.
- A crop audit whose asset inventory, page, rectangle, output, package state, or alt text differs from the current ledger.
- A title-only crop containing unaccounted effect prose, price, map, neighboring label, or partial source sentence; a Choice layout that neither renders its intact source panel nor records and renders a measured-fragments decomposition justified by direct narrow comparison.
- One decomposed member visually dominating equivalent intact siblings without a source-authored distinction that justifies the mixed strategy.
- Summary-only alt text on a text-bearing source panel whose exact wording is not otherwise available as live semantics.
- Source prose repainted as live system text with materially different typeface, weight, wrapping, hierarchy, or responsive height instead of measured paragraph/block panels.
- A full-width source banner constrained into a shallow fixed-height `contain` box with large letterboxing or microscopic instruction text; preserve its natural aspect ratio.
- A text-bearing raster panel reported as microscopic at a required width without finer decomposition or a demonstrated responsive-fidelity gap.
- A `responsiveHeightInflation` finding where a narrow Section grows beyond three equal-width source heights without finer group composition or a demonstrated responsive gap.
- Extra shared-gutter pixels retained on repeated sibling crops, a fitting two-track 720px Grid collapsed by a generic breakpoint, or a narrow rail with unexplained empty height beyond its live elements.
- An additive rail whose width, outer frame, or edge alignment does not visibly belong to its source panel, including a rail that disappears into a same-color Section where the source card has an accent boundary.
- A non-structural seam between adjacent panel crops, any word or line divided between sibling images, or shared parent content repeated or separated when those siblings responsively stack.
- Any Choice, Source, control, selection state, property, or outcome projection for final Home/Stay/Next outcomes. Exact prose and visuals without interaction are required.
- Generic checkbox/radio activation in place of a native integer, select, text, continuity, or either-resolution control.
- A `select` control with zero options, or an unrestricted text control with no meaningful placeholder and no manual observation containing a nonempty typed value different from unset.
- A scalar input repeated across tier, rarity, price, or classification Choices instead of one direct scalar owner that creates the stable grant exactly once plus mutually exclusive classification members; duplicated tier grants, a Companion upgrade using Form ownership, a Form upgrade using Companion ownership, any other untargeted upgrade, or any non-toggle Source member without a source-evidenced two-stage contract.
- Any interaction that unexpectedly reveals its primary control or shifts neighboring layout after selection.
- An avoidably wrapped primary-width scalar rail when the measured Roll/value/Clear/Cost group fits in one row, or adjacent scalar cards whose action rails do not share a deliberate baseline and spacing system.
- A panel and live rail that do not read as one bounded card; mismatched outer edges; an accent frame that stops before the rail; a rail that merges into the Section background; or a simple Control and Cost clustered on one edge despite source-consistent space on the other.
- Any action whose observed value or resolved Cost does not prove the named state, any live-element overlap at 1440/720/390, or any stable-contract bound changing by more than one CSS pixel.
- Missing alt text, package diagnostics, or unexercised interaction paths.
- A finite source option domain modeled as unrestricted text; a cross-choice discount/free entitlement shown only in isolated screenshots; a repeated quantity proven only by its rank input; or unconditional inventory never opened and inspected.
- A repeatable discounted Choice whose same-state evidence hides the resolved total through compact Cost density or accessible-only text.
- A roll-or-pay Source whose manual price was verified for only a representative member while an exceptional member (including a nested Free Pick) bypasses that price.
- A visual mismatch dismissed only because the archive imports or the pixels are approximately similar.
- Any source page, output Section, required width, acceptance category, comparison sheet, or evidence file missing from the ledger.
- A missing independent review, any open independent finding, or a review marked passed by the converter without a fresh-context reviewer.
- A missing, stale, or hand-edited `review-evidence.json`, or an independent review performed before regenerating that factual manifest from the final interaction records.
- An authoritative experiment report whose claimed shipped/selected alternative no longer matches the current JDEF and captures; move superseded reports to `verification/rejected/`.
- A partial package offered because the source is large or the current turn is ending. Resume and continue instead.

## Handoff

Report the absolute archive and project paths, source hash, verification result, uncertain transcription, accessibility/reflow limitations, remaining gap IDs, and a source-page coverage table naming the mapped Sections and comparison evidence. Do not commit anything under `scratch/`.
