Accepted technical baseline

Application architecture

One offline-first application codebase runs primarily as a packaged Tauri desktop app and secondarily in an ordinary browser. Pure domain and rendering code is shared; environment-specific capabilities enter only through explicit ports.

Status: accepted baseline. Windows, Linux, and macOS are equal targets. Browser operation is supported but is not the primary user surface. Rust is an accepted contributor requirement. Signing and notarization are distribution concerns and do not constrain the architecture.

Architecture Drivers

  • ship one application and one product experience rather than separate desktop and web products
  • run fully locally with no hosted backend, paid service, commercial component, account, or telemetry dependency
  • develop and exercise the complete interface in a normal browser
  • package native artifacts for Windows, Linux, and macOS without adopting platform-specific application logic
  • treat Jump packages, chain archives, assets, markup, and Story content as untrusted input
  • share parsing, evaluation, rendering, supplement, and interaction behavior between Editor preview and Chain Tracker
  • keep persistence and operating-system APIs replaceable and directly testable

Desktop and Browser Profiles

Desktop profile

  • The Tauri package is the primary supported user surface.
  • Each operating system receives its normal native artifact from the same source tree. One binary is not expected to run across all operating systems.
  • SQLite, native dialogs, application-data storage, content-addressed package files, and atomic filesystem replacement are provided by Rust commands.
  • Unsigned packages are allowed. The architecture does not depend on a signing service, store, updater, or paid distribution account.

Browser profile

  • The same compiled React application runs against browser adapters and remains useful beyond automated testing.
  • IndexedDB stores application state. File inputs and downloads provide portable import/export; optional browser file APIs may enhance convenience but are never required.
  • No local companion server is required. A static development or production build is sufficient.
  • Browser capability limitations are surfaced honestly. The UI never pretends an IndexedDB record is a durable external project folder.

Editor Workspace Ownership

Desktop authoring projects use a user-selected external directory as their canonical source. The directory contains jump.jdef, optional choices.jdef and layout.jdef, and assets/. This keeps projects compatible with version control, ordinary text editors, filesystem tools, and manual backups.

  • SQLite stores the workspace registry, recent-project metadata, search/diagnostic indexes, and recovery bookkeeping; it is not the authoritative source for project text or assets.
  • An application-data recovery mirror retains versioned unsaved/autosave state so temporary permission loss, unavailable drives, crashes, or interrupted writes do not silently discard work.
  • The recovery mirror never silently replaces newer readable project files. Recovery is an explicit comparison and restore operation when disk and mirror differ.
  • Installed .jmp packages are immutable content-addressed library copies and are never edited in place. Editing an installed package first creates or selects a separate authoring project.
  • Browser projects are owned by IndexedDB because durable external-directory access is not assumed. Source-project import and export move them between the browser and ordinary files.
  • Desktop and browser workspaces implement the same workspace repository contract even though their durability mechanisms differ.

External Project Changes

Desktop workspaces watch their canonical project directory for changes made by other editors, version-control tools, and filesystem operations.

  • If the affected file has no unsaved Editor changes, the application reloads it automatically and refreshes diagnostics and preview.
  • If the affected file has unsaved Editor changes, autosave for that file pauses and the Editor presents Compare, Keep Editor Version, and Use Disk Version. Neither version is discarded before the author resolves the conflict.
  • Keep Editor Version writes the Editor buffer as a new deliberate save. Use Disk Version replaces the buffer only after the disk version has been preserved by recovery bookkeeping.
  • External asset changes reload automatically unless the application is simultaneously replacing that asset, in which case the same conflict rule applies.
  • An unavailable directory or lost permission is treated as a recoverable workspace outage, never as an empty project. The recovery mirror remains available until the canonical directory can be read again or the author explicitly restores elsewhere.

Dependencies point inward: UI and adapters depend on application/domain contracts; domain code never imports React, Tauri, SQLite, browser globals, or filesystem APIs.

Localization initializes English before React mounts, then applies the validated persisted language before the application surface is shown. Bundled JSON packs are untrusted text resources subject to the schema, bounds, known-key, and token-parity policy in Localization Resources.

Domain State and Commands

  • Packages are immutable values identified by their complete archive hash.
  • Chains, Editor workspaces, settings, and tag profiles are separate aggregates with explicit schema versions.
  • User actions enter through commands that validate intent, produce a new authoritative state, record undo information where applicable, and commit through one repository transaction.
  • Budgets, conditions, grants, historical views, and supplement effects are pure derived calculations. Persisted snapshots needed for unresolved packages are explicitly versioned state, not an accidental cache.
  • React observes application services through narrow stores/subscriptions. React component state is limited to ephemeral view concerns.

Markup and Renderer Pipeline

Source text
  → Lezer concrete syntax tree
  → typed format AST
  → schema and semantic diagnostics
  → canonical package model
  → evaluation model
  → shared renderer
  • Lezer’s recovery tree supports active editing but never replaces semantic validation.
  • The typed AST, not the Lezer tree, is the stable application boundary.
  • Structured edits and Quick Fixes produce minimal source edits. Source remains canonical.
  • The same renderer executes in Editor preview and Chain Tracker; preview swaps persistent state for a disposable sandbox.
  • Renderable text is tokenized into an allowlisted model. Imported text never reaches dangerouslySetInnerHTML, raw CSS, or executable browser content.

Current implementation: generated first-run .jdef sources pass through this complete boundary into immutable exact-hash package models. The Chain Tracker uses the same layout and control renderer contract intended for the Editor; the Editor supplies disposable preview state when its UI is implemented.

Evaluated Gauntlet Boundary

Gauntlet behavior is a derived entry condition shared by the renderer, resource ledger, Chain Tracker, and supplements. Consumers never infer it from a package name, tag, displayed balance, or the presence of a particular drawback.

Persistence Model

Desktop storage uses a hybrid SQLite and content-addressed-filesystem model:

  • SQLite stores searchable metadata, aggregate versions, relationships, migration state, and transactional JSON payloads.
  • Installed .jmp archives live under application data by SHA-256 rather than as database blobs.
  • Complex chain and supplement state stays in versioned aggregate payloads instead of being fragmented into UI-shaped relational tables.
  • Indexes duplicate only stable fields needed for lists and search. Aggregate payloads remain authoritative.
  • Autosave commits one aggregate transaction. File exports use write-to-temporary, flush, and atomic replacement where supported.
  • Every persisted schema has ordered, deterministic migrations and recovery tests.

Browser IndexedDB uses the same aggregate and index split. Repository contracts define behavior, not SQLite-specific queries.

The current chain aggregate persists exact package references, actor selections, nested inputs, roll provenance, entry-scoped Gauntlet sources, enabled-module state, and supplement state through IndexedDB or the SQLite-backed Tauri aggregate store. Derived balances, properties, records, Companions, tags, and summaries are recomputed on load rather than persisted as UI-shaped truth.

Maintained development fixtures cross an explicit Mock boundary rather than masquerading as built-in or imported content. The reserved Morgan identity gives the saved-chain registry Mock provenance without changing the chain aggregate schema. Its three packages carry Mock provenance in the package catalog, and the persisted default-off developer setting controls only list and Library exposure. Reset saves a newly cloned canonical aggregate before publishing it to application state, so storage failure cannot partially replace the active fixture or affect user-owned chains.

Editor Repository and Package Boundary

EditorWorkspaceRepository separates versioned summaries, snapshots, revisions, recovery, and external conflicts from React. Browser projects use the dedicated IndexedDB workspace store. Desktop folders remain the canonical source and SQLite retains the registry/recovery aggregate; source writes use temporary-file replacement and a recovery mirror. Confirmed project deletion removes the browser record or desktop registry/recovery entry atomically without deleting an external canonical project folder. Confirmed chain deletion removes its aggregate; an initialized-empty registry remains distinguishable from first launch so deleted fixture content is never silently reseeded.

The Source surface is a CodeMirror document view over the same authored files used by Structured. Parsed fields carry exact declaration, name, condition, and value ranges; Structured operations resolve those ranges at command time and reject stale or ambiguous targets. Source, Structured, layout, conditional-variant, declaration, and asset commands enter one package history, with continuous Source input and focused Structured sessions coalesced independently.

JumpPackageImportService is shared by Editor and Chain Tracker. Editor commits a validated authoring copy; Chain Tracker commits an immutable content-addressed package. Both operations are staged and atomic. EffectivePackageSizeLimits is created only from validated settings and is the only size-budget type accepted at archive and native folder boundaries.

Direct asset authoring reuses the package boundary’s signature, polyglot, geometry, and full-decode validation rather than maintaining a weaker Editor-only image checker. Effective asset byte limits are checked before decode, and failed selection leaves package state and history unchanged.

Trusted Native Boundary

  • Rust owns bounded ZIP inspection, entry/path validation, streamed decompression limits, bounded graphical asset decoding, SQLite access, desktop folder containment, recovery mirrors, and final atomic file operations.
  • archive-core is written without Tauri dependencies and compiled natively for desktop and to WebAssembly for browser imports, minimizing security-rule drift.
  • The frontend receives validated bounded data and structured diagnostics, never unrestricted native paths or a shell/command-execution primitive.
  • Tauri capabilities grant only the commands needed by the main application window. Remote navigation and arbitrary child webviews are disabled.
  • All upstream links open through a validated HTTPS external-navigation command.

Testing Architecture

  1. Vitest Node tests cover pure parsing transformations, validators, commands, evaluation, supplements, migrations, and serializers.
  2. Vitest Browser Mode covers components requiring real layout, selection, focus, input, and browser APIs.
  3. Playwright runs complete browser-profile workflows in Chromium, Firefox, and WebKit with deterministic adapters and visual artifacts.
  4. Cargo tests cover archive attacks, hashing, path containment, SQLite transactions, migrations, and filesystem recovery.
  5. Repository and archive contract suites execute against every implementation.
  6. A small WebdriverIO suite exercises the built Tauri application, IPC permissions, native dialogs through controlled adapters, and startup/recovery on each operating system.

ADR: Tauri Shell with Shared Browser Runtime

Status
Accepted
Context
The product needs local files, persistence, and native packages without maintaining a separate browser product or purchasing a runtime/component license.
Decision
Use Tauri 2 around one React/TypeScript/Vite application. Put domain logic in pure TypeScript, privileged persistence and filesystem operations behind Rust commands, and supply browser adapters for the same ports.
Consequences
Contributors need Rust and Node/pnpm. Each operating system needs its own build. Webview differences require Chromium/WebKit coverage. Most UI and domain development remains ordinary browser work, while native security and persistence receive focused Rust and packaged-app tests.

Architecture Status

No architecture decisions block implementation. The platform, runtime profiles, workspace ownership, external-change handling, primary module boundaries, persistence direction, security boundary, and test layers are settled. Detailed implementation planning may refine internal code organization without replacing this accepted baseline.
