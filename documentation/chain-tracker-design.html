Chain workspace draft

Chain Tracker design

An ordered, persistent chain workspace for choosing jumps, making selections through the shared Jump renderer, and inspecting everything accrued at any point in the chain.

Status: workspace direction settled for the current scope. The major surfaces, reordering review behavior, chain-wide supplements, immutable package versions, markup-derived companion viewpoints, and always-editable Jump entries are established. Supported supplement modules are discussed in Supplements Design.

Purpose and Boundary

The Chain Tracker owns a user’s durable chain record. It consumes validated Jump packages but never edits their source. The initial workspace must support:

  • an ordered list of jumps already in the chain
  • a library of built-in and imported jumps available to add
  • drag, keyboard, and button-based jump reordering
  • the current jump’s interactive choices, costs, and rolls
  • perks, items, and companions accrued through any selected chain point
  • tag filtering over accrued perks and items
  • alternate forms accrued through the chain, with the same historical inspection pattern as companions
  • supplements that can be enabled, disabled, opened, and configured, including persistent foundations such as Body Mod

Core State Model

A chain contains ordered chain entries, not merely package references. Each entry has its own stable ID, immutable installed-package version, choice state, rolls, grants, and validation status. Supplement state is owned once by the chain. The same logical package may appear at different installed versions without attaching accrued content to a fragile array index. The user setting gates only an interactive attempt to add a second version; it does not govern imported or already-present entries.

Current jump

The entry open for choice interaction. Selecting a chain entry also makes it the default historical cutoff.

Inspection point

The inclusive “through this jump” boundary used by Perks, Items, and Companions. It may be changed without opening another jump.

Jump library

Validated built-in and imported packages available to add. Library membership is independent from chain membership.

Supplements

Chain-wide, application-defined rule/content layers with explicit enabled state and their own selections. The supported set and module-specific behavior are documented separately.

Reordering and Historical Views

Accrued records refer to the stable ID of the chain entry that granted them. Chronological numbering still begins with Jump 1, but the list renders newest-first: the most recent entry is at the top and Jump 1 is at the bottom. Reordering changes chronology and therefore changes what appears at each historical cutoff, but it does not detach a perk, item, or companion from its originating entry. Reordering remains freely available. The default-off chain.warnUpstreamChanges preference may request review before a reorder or deletion invalidates an explicit active downstream reference, such as moving a companion provider after a Jump that imports that companion. Ordinary record-volume and historical-cutoff changes never trigger the warning. Every committed reorder or deletion remains undoable.

No Completion State

A Jump entry is never completed, finalized, locked, or reopened. Users may make any number of choices—including none—and may return to edit any entry at any time. The tracker continuously recalculates costs, grants, historical views, and downstream diagnostics from the current state.

Shared Jump Renderer

The Editor preview and the Chain Tracker must use the same package renderer, layout engine, condition evaluation, choice controls, roll controls, and responsive behavior. The renderer receives a state adapter:

  • Editor preview adapter: temporary, non-persistent choices used to inspect authoring changes.
  • Chain adapter: durable choices, rolls, costs, grants, and diagnostics associated with one chain-entry ID.

This keeps a Jump from looking or behaving differently when authored and when actually used. The tracker surrounds the shared renderer with chain chronology, inventory, companions, and supplement tools; it does not fork the renderer.

Interactive Workspace Draft

Use the five primary workspace tabs, newest-first chain, reorder controls, library, historical selectors, tag filters, choices, rolls, and supplement subtabs. The mock keeps a fixed workspace frame and scrolls each page independently. This fixture assumes the parallel-package-version and negative-point-balance settings are enabled so both states can be exercised.

Workspace Rules Captured by the Mock

  1. Chain & Jump, Inventory, Forms, Companions, and Supplements are independent full workspace pages rather than persistent side panels surrounding one main page.
  2. Selecting a chain entry keeps the Chain & Jump page open and sets the inspection point to that entry.
  3. Changing only the inspection point updates Inventory, Forms, and Companions without changing the open Jump.
  4. Inventory combines perks and items, can filter to either kind, and reuses relationship-aware search behavior from Tag System Design. Its Stats subtab summarizes perk tags only and does not include items.
  5. Selecting an Inventory result opens its complete record—including source, tags, and description—in a reusable perk/item detail overlay.
  6. Forms use the same historical roster-and-detail interaction as Companions. They are accrued records to inspect, not mutually exclusive states to activate. Each form’s full-details overlay shows form-specific properties and perks, and those perks open the shared record-detail overlay.
  7. Reordering preserves each entry’s identity and grants, then recomputes historical views and dependency diagnostics. With upstream warnings enabled, only a reorder that would invalidate an explicit active downstream reference requires review before it commits; the preference is off by default.
  8. The × control removes a chain entry while preserving the source package in the library. The removed entry’s choices, rolls, grants, and actor state are deleted rather than retained for a later re-add. Up, down, drag, and remove controls use the same compact action pattern as layout editing.
  9. The library identifies built-in versus imported provenance and always distinguishes separately installed versions. Adding an exact version already in the chain focuses its entry. When the user invokes Add for another version of the same logical package, that one action is permitted only by the user setting. Importing a chain, installing packages, disabling the setting later, and using entries already in the chain do not consult it. Multiple present versions are always surfaced on chain entries and historical selectors.
  10. The current-jump summary exposes currency, origin, gender, and age without consuming renderer space. Switching the active actor loads separate choice state. A companion appears in the actor selector only after that companion exists in the chain and an active companion-import grant selects their stable identity for the current entry, with or without an initial resource budget.
  11. The compact summary keeps the primary currency and origin names visible. Hovering or focusing Currency shows the active actor’s remaining alternative currencies. Hovering or focusing Origin shows its description and the separately selected Location choice, or “None selected”; an Origin never assigns or implies a Location.
  12. The Supp button beside + Add opens an overlay without resizing the workspace. It lists only enabled supplement tools for the selected Jump, and updates its title and content when another Jump is selected.
  13. Negative point balances are disabled by default. When disabled, the renderer blocks a selection that would create or worsen a deficit. When enabled, the Jumper and any imported companion granted a positive point budget may overspend; zero-budget participation never gains that permission.
  14. An allowed deficit turns the current balance red, marks the affected companion option in the actor selector, and marks the Jump in both its header and chain entry. These indicators clear automatically when every actor returns to a nonnegative balance.
  15. The companion detail can open a route-style overlay showing that companion’s perks, items, and Jump import history. Selecting one of its perks or items opens the same record-detail overlay above the companion profile rather than replacing it.
  16. Supplements are chain-wide and application-defined rather than author-defined markup packages. The Supplements page always retains a Manage subtab. Each enabled supported supplement gains its own content subtab; disabling it hides that reserved subtab without deleting its selections or shifting adjacent controls. Module-specific main pages and current-Jump tools belong to Supplements Design.
  17. Jump entries have no completion state or minimum-choice requirement. They remain editable for the life of the chain.
  18. All choice and roll interaction inside Jump or supplement content uses the shared renderer contract.

Persistence and Recovery

  • Choice changes, rolls, reordering, and supplement toggles autosave with the same explicit-save fallback available elsewhere in the application.
  • Enabling or disabling a supplement recalculates every Jump and historical view. Disabled modules retain their choices and records but contribute no active rules, grants, costs, restrictions, or resource transformations.
  • A supplement toggle never fails or deletes purchases merely because recalculation creates a deficit. The resulting recovery deficit is allowed regardless of the ordinary negative-balance setting; deficit-reducing changes remain available while deficit-worsening changes remain blocked.
  • Each chain entry is permanently associated with the installed package version used to create it. Installing another version does not alter or migrate that entry.
  • In-chain package updating and migration are not supported. To use a different version, the user removes the old entry and adds the separately installed new version, accepting the normal removal impact review and rebuilding its selections.
  • Removing a package from the library does not destroy chain entries already based on it; the stored snapshot remains usable.
  • An installed version that becomes unavailable leaves its chain entry recoverable from retained chain data; the application does not silently substitute another installed version.
  • Reordering and deletion are undoable. When chain.warnUpstreamChanges is enabled, a change that would invalidate an explicit active downstream reference receives pre-commit review. Unrelated changes commit without confirmation, and disabling the preference skips review without weakening validation or Undo.
  • Removing a jump is also undoable and reports any grants, companion imports, forms, or downstream dependencies that will leave the active chronology.
  • Negative balances are ordinary persisted actor state when permitted. Turning the setting off does not silently undo choices; it blocks changes that worsen an existing deficit while allowing refunds and deselections that move toward zero.

Accessibility and Safety

  • Every drag operation has equivalent up/down controls and keyboard ordering support.
  • Tabs, chain entries, tag filters, choice controls, and supplement toggles expose selected state programmatically.
  • The contextual supplement overlay is keyboard reachable, identifies the selected Jump, exposes each selected tool programmatically, and closes with Escape while returning focus to Supp.
  • Historical filtering announces updated counts without moving focus or resetting the current workspace tab.
  • Imported packages, Markdown, images, and assets remain untrusted and use the same sanitization and permission boundary as Editor preview.
  • Roll outcomes are announced and stored; animation is never the only indication that a roll completed.
  • Disabling a supplement never silently deletes its selections. The state remains available if it is re-enabled.
  • The companion and form profile overlays follow the same focus containment, Escape-to-close, inert-background, and focus-restoration rules as Settings.
  • When overlays are stacked, only the top overlay receives interaction. Closing a perk/item detail restores focus to its invoking Inventory card, companion record, or form-perk record, leaving the underlying profile open.
  • Negative balance state is communicated by signed point text, warning language, and an icon in addition to red styling.

Current Design Status

Implementation preview available. The reusable tracker workspace is exercised at /review/chain-tracker with dense deterministic data. Product persistence and the shared Jump renderer remain separate implementation passes; the mock above remains the visual and behavioral authority.

No Chain Tracker workspace questions are currently open. The supported supplement set and its current module-specific decisions are settled in the dedicated supplement document; implementation may expose practical issues that require revisiting these rules.
