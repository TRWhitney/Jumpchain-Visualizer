Shared renderer contract

Controls

One visual library for manual controls, ranked costs, mutually exclusive and independent selections, and random resolution across Editor preview and the Chain Tracker.

Status: agreed control catalogue. Markup owns the semantic fields. This page owns their neutral default rendering and behavior.

Rendering Contract

  • Rendered Jump controls use neutral renderer defaults. Application accent colors never leak into selection state.
  • Single select uses radio buttons so mutual exclusion is visible. Multi select uses checkboxes so independent selection is visible.
  • Selection does not recolor or outline an entire choice. The native control, its label, and accessible state communicate selection.
  • Normal costs show resolved amounts. Discounts strike the old cost beside the new cost in restrained green. Free costs read Free in the same green.
  • Ranked costs show the price per rank, selected rank count, and cumulative total in one badge.
  • Flat and select rolls make the recorded value Free. Moving away applies normal cost; returning restores Free.
  • A ranked roll grants that many free ranks. Selecting fewer remains Free; selecting more charges only for ranks above the rolled allowance.
  • Random-only controls never display an unused authored price. Their badge changes from Roll for Free to Free · Rolled.
  • Every roll locks after its first result unless Allow rerolls is enabled. The button remains labelled Roll.
  • Clear is disabled whenever its control is already unset and re-enables only when there is a current value or selection to remove.

Control Library

The markup construct choice-source mode: single renders a Single select control; mode: multi renders a Multi select control. “Source” is document vocabulary, not a separate kind of user-facing control.

Nested inputs: text, integer, and select inputs reuse the same neutral fields above. Companion roster selection is a checkbox list of existing companions. Nested inputs require an authored layout leaf and therefore are not additional default-choice control modes.

Persistence

  • Roll occurrence and result are stored separately from the current selection.
  • A random-only integer may be cleared back to unset without deleting its stored result. With rerolls disabled, Claim restores that result without rolling again.
  • Unselecting a rolled multi-select option removes the acquisition but retains its Free badge and roll provenance; checking it again reacquires it for Free.
  • Rerolling replaces the recorded result and unselects the former result. Removing the chain entry deletes both selections and roll records.
  • Editor preview uses the same interactions in nonpersistent sandbox state.
