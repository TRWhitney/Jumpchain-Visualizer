Application context-menu audit

The application uses one localized, theme-aware menu primitive for useful object actions and one explicit native-menu policy for the remaining application surface.

Overview Application Architecture Context menus

Decision

Status
Accepted and implemented
Context
Generic Back, Forward, Save, and Inspect browser chrome does not help with most application-owned objects. The Editor explorer had a useful custom menu, but its implementation and styling were feature-local.
Decision
Render one body-level fixed menu through ContextMenuProvider. Features provide stable action IDs, localized labels, disabled and danger state, separators, and callbacks that reuse their visible commands. The provider owns placement, focus, dismissal, RTL behavior, and native-menu suppression.
Consequences
Application objects gain consistent pointer and keyboard actions without creating a second command path. Editable or selectable content retains browser editing affordances. A context menu remains a convenience: every command has a visible or otherwise keyboard-accessible workflow.

Native-menu boundary

Application-owned, non-editable chrome cancels an unhandled contextmenu event inside the provider scope. This includes blank surfaces and Settings navigation. Settings also suppresses the generic menu on non-text controls such as dropdowns, checkboxes, and the standalone color picker. Text-entry fields—including the text segment of a compound color control—retain ordinary Cut, Copy, Paste, selection, and spelling behavior. One narrow override applies to a misspelled word in an English Structured natural-language field: right-click opens the application's offline dictionary suggestions. Shift+right-click preserves access to the native editing menu.

Text inputs, textareas, contenteditable and CodeMirror regions, selectable reports, links, images, media, and an active text selection preserve the native menu except for that explicit spelling override. Correct words and fields without an application dictionary continue directly to the native menu. Source editors, authored rendered content, dialogs, global navigation, Jump choices, inventory and companion cards, package-library cards, radar charts, conditional variants, and supplement purchases do not receive feature menus.

Suppression is presentation only. It is not a security boundary and does not prevent developer-tool access. Firefox intentionally permits Shift+right-click to bypass the scripted event.

Interaction and localization contract

  • Pointer menus open at the event coordinate; Shift+F10 and the Context Menu key open beside the focused target.
  • The measured menu clamps to both viewport axes. Inline keyboard placement and alignment follow document direction.
  • Initial focus enters the first item. Up and Down wrap; Home and End jump; Enter and Space activate; Escape and Tab dismiss; outside pointer, window blur, resize, and scroll dismiss.
  • Disabled items remain in the menu with aria-disabled but never execute. Dismissal restores focus when appropriate.
  • Generic verbs live in common.json. Object-specific accessible names and interpolated labels live in feature catalogues. English is authoritative; partial Spanish and Arabic fixture packs exercise fallback, interpolation, and RTL.

Verification ledger

  • Browser component coverage exercises pointer and keyboard opening, wrapped focus, disabled and danger actions, dismissal, actual measurement, RTL containment, and native-menu preservation.
  • Settings coverage dispatches the exact event on navigation, dropdown, standalone color, and text-entry controls.
  • Playwright covers project and chain records, Earth and ordinary chain entries, Editor explorer and authoring rows, raster layers, tag entries, and diagnostic events by right-clicking the actual target and asserting the visible result.
  • Ordinary verification never updates tracked review artifacts. Fresh light, dark, and Arabic RTL captures are retained only in test output when the artifact workflow requests them.
