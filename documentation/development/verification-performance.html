Living engineering playbook

Fast feedback without weaker evidence

Reduce wall time by exposing safe parallelism, reusing validated work, and measuring the actual critical path. Coverage, browser intent, observable acceptance criteria, and the no-retry rule remain fixed guardrails.

Decision: remove duplicated browser-engine work instead of adding workers. Every product behavior runs in Chromium; a contract-protected engine-risk matrix runs in Firefox and WebKit. Unit work is isolated from browser-component and Rust work on WSL. Production rendering is unchanged.

Baselines were captured on Linux under WSL with 32 available CPUs, 94 GiB RAM, Node 24.18.0, pnpm 11.11.0, and Rust/Cargo 1.89.0. A warm measurement reuses compiler and formatter caches; a cold measurement begins after the relevant cache has been removed. Compare timings, test counts, and failures—not one favorable run. WSL repeatedly crashed Node workers when unit, browser-component, and Rust pools overlapped, even after a WSL restart and after moving from child-process forks to worker threads. The accepted verifier therefore isolates unit execution in its own wave.

A follow-up tsc -b --verbose inspection showed that the earlier TypeScript strategy only wrote build metadata: both no-emit projects were still declared out of date on every invocation because src/main.js and playwright.config.js intentionally do not exist. Independent tsc -p invocations with incremental enabled preserve the same strict project coverage and reduced the measured warm median from 7.41 seconds to 1.84 seconds. A temporary-project contract changes a previously clean source into a type error after the first run, proving the cache invalidates instead of hiding new diagnostics.

The first finished-code exhaustive tier passed all 565 product tests at 3 workers in 14.4 minutes. After reusable state, the exhaustive verifier passed the same 565 assignments plus its setup test in 801.9 seconds, or 13.2 minutes of Playwright execution and 802.17 seconds including package-manager startup. The sustained Chromium suite previously produced a retained 12-worker target crash after 190 of 191 tests and an 8-worker pass that missed the full-gate budget by 1.3 seconds. A Firefox screenshot also exposed locale hydration rather than a missing menu: the menu was visible in English before persisted Arabic state loaded, so the exact path now waits for observable lang="ar" and dir="rtl" state. No retry converted any failed run into a pass.

The reusable-state stress campaign retained one instructive failure instead of retrying it away. The first snapshot included a 2.2 MB pretty-printed payload with an encoded Morgan demonstration chain that ordinary onboarding state did not need; after three green runs, a fourth context failed while restoring that large IndexedDB value. The setup now keeps the UI-produced settings record, preserves every object-store definition, and removes unrelated records before writing the 290 KB ephemeral snapshot. Home, mock-data gating, and Morgan behavior remained green, followed by three complete 192-test Chromium passes at 87.29–87.66 seconds.

The next investigation separated test-harness cost from product architecture. A deterministic prepared-editor snapshot removed repeated Open Editor/Create Project actions, but its exhaustive candidate reduced summed work only from 2,229 to 2,092 seconds and failed two WebKit assertions. Because the 6.1% improvement missed the 10% acceptance threshold, the snapshot and fixture option were removed. Success-only diagnostic captures remain artifact-mode-only, while screenshots used by assertions and automatic failure evidence remain.

A production route-splitting probe reduced the generated entry bundle but broke rendering. It was reverted immediately, the production source and Vite configuration were verified identical to the prior commit, and the original client was rebuilt before browser verification continued. This establishes a hard boundary for future work: a verification optimization must not change production rendering unless the product change is independently justified, specified, and verified.

The substantial reduction came from questioning engine duplication. The old exhaustive tier reran almost every ordinary application scenario in all three engines: 197 Chromium, 184 Firefox, and 184 WebKit assignments. The accepted matrix runs all 197 behaviors in Chromium and 14 contract-selected engine risks in each secondary engine, covering history/focus, persisted chain creation, responsive layout, image decoding, drag-and-drop, source keyboard handling, canvas, radio controls, IndexedDB, RTL, Settings overflow, review layout, module keyboard behavior, and welcome-tour persistence. This reduces the authoritative Playwright listing from 566 results to 226 without raising the three-worker cap.

The final matrix passed all 226 results in 299.88 seconds. Its ignored performance report recorded 780.9 summed test-seconds, 429.6 navigation seconds, 18.3 context seconds, 17.3 page seconds, and 0.4 screenshot seconds. Against the 801.9-second verifier baseline, the browser wall fell by 62.6%; against 2,229 summed test-seconds, executed work fell by 65.0%. This is a coverage-allocation change, not a cached result: every product test still executes in Chromium on every exhaustive run.

Strategies already in use

Verification tiers

The everyday, full, exhaustive, and release gates add evidence according to risk rather than running the packaged application for every edit.

Guardrail
The contract test enumerates every gate so a performance refactor cannot silently omit one.

Focused browser intent

Chromium carries every product behavior. Firefox and WebKit carry an explicit engine-risk contract in both full and exhaustive verification instead of duplicating ordinary application scenarios.

Guardrail
A contract inventories all 14 secondary-engine behaviors and fails if a required @cross-browser assignment disappears.

Build reuse

The verifier proves the production client build once, then sets E2E_SKIP_BUILD=1 for Playwright tails.

Guardrail
Native release verification owns its separate packaged build.

Observable acceptance

GUI tests exercise the reported target, action, and post-action state. Screenshots and direct assertions outrank implementation proxies.

Guardrail
Retries never convert an unstable result into a pass.

Incremental compilation

TypeScript no-emit projects retain semantic build state through tsc -p, while Rust keeps its incremental artifacts. Both make repeated local gates cheaper without caching a test result.

Guardrail
Caches improve execution only; they never decide what receives coverage, and a changed-source contract proves TypeScript invalidation.

Execution improvements adopted

Expose browser file parallelism

Vitest Browser Mode runs explicitly headless. Without that explicit state, the browser pool serialized files and left most CPUs idle.

Accept
All 78 tests pass repeatedly with a median below 10 seconds.
Rollback
Remove the headless flag if browser-provider correctness changes or file isolation fails.

Scale Playwright workers

Local workers never exceed available CPUs or 12. The short Chromium smoke path may use 12, sustained Chromium uses the measured stable cap of 9, focused Firefox/WebKit uses 8, and exhaustive execution retains 3. CI also remains at 3 to respect shared-runner constraints.

Accept
Repeated suites remain stable and materially beat the 3-worker baseline where the browser and workload support it.
Rollback
Lower a browser or workload cap if failures correlate with resource saturation after observable waits are correct; the retained 12-worker target crash is why one cap need not fit every workload.

Make no-emit state effective

Run independent no-emit TypeScript projects with tsc -p and explicit incremental state. Build mode is appropriate when emitted project-reference outputs exist; it was not an up-to-date check for these intentionally output-free projects.

Accept
Warm typechecking stays below 2.5 seconds and a post-cache source error is still reported.
Rollback
Return to a single invocation if the projects gain real declaration dependencies or cache invalidation becomes unsound.

Isolate the unit pool

The 547 unit tests retain eight worker threads but run in their own verifier wave. Vitest documents that threads use worker contexts while the default forks pool uses child processes. Isolation avoids the WSL kernel failure repeatedly triggered when unit, browser-component, and Rust pools overlapped.

Accept
The suite remains near six seconds and the complete everyday gate exits cleanly.
Rollback
Merge waves only after the actual host kernel/toolchain combination proves repeated mixed-wave stability.

Reuse browser storage state

A Playwright setup project dismisses onboarding and selects the Advanced interface through the real UI once, then captures cookies, local storage, and IndexedDB beneath ignored test output. Each product test receives an isolated copy; the three first-launch tests explicitly request empty state.

Guardrail
The snapshot is regenerated every invocation, contains no cookies or non-local origins, adds one setup test, and never replaces the real welcome-tour journeys.
Rollback
Restore per-test setup if any engine cannot load the state or Chromium improves by less than ten percent.

Rejected: prepared editor state

A UI-derived blank workspace was technically isolated and portable, but reduced exhaustive summed work by only 6.1% and complicated empty-state intent.

Decision
The implementation was removed because it missed the predefined 10% category threshold.
Lesson
Measure the complete workload before institutionalizing fixture complexity.

Capture diagnostics on demand

Ordinary passing runs no longer write screenshots whose pixels are never asserted. Pixel checks, Playwright failure screenshots, and the explicit artifact workflow remain unchanged.

Accept
Normal screenshot time and output fall while failure and review evidence remain available.
Rollback
Restore a capture when it is an actual assertion input or required review artifact.

Measure browser work categories

A lightweight reporter records ignored project, file, test, navigation, context, page, screenshot, and action timings without source or application state.

Use
Distinguish repeated harness work from product execution before choosing an optimization.

Keep reports non-blocking

The HTML report is still generated but uses open: "never". Developers open it deliberately with pnpm test:e2e:report.

Accept
A failed Playwright command exits and releases its process group instead of serving a report indefinitely.
Rollback
Automatic opening may return only if it cannot hold verification open.

Cache content checks

ESLint and Prettier cache by file content. Warm formatting and linting skip unchanged inputs; ESLint concurrency stays disabled because its cold memory cost outweighed the gain.

Guardrail
Content hashing prevents timestamps alone from declaring a changed file clean.

Model dependencies and resources

Static checks run first, unit tests run alone, then build, browser components, and Rust checks share a bounded wave. Playwright tails start only after the validated production build exists.

Guardrail
Treat repeated worker crashes and teardown stalls as scheduling evidence; do not recover them with retries or repeated WSL restarts.

Print the critical path

Every verifier run reports command, wave, critical-path, failure, and total elapsed time.

Use
Optimize the longest command in each sequential wave; shortening non-critical siblings may not change wall time.

Wait for readiness, not time

The Settings journey polls visible section identifiers after tab changes, waits for persisted locale attributes after navigation, and waits for the tour's actual dialog lifecycle before yielding shared setup.

Guardrail
No sleeps and no retries; failure still identifies an unmet observable state.

Rust artifact policy

The original cache accumulated many hashed dependency variants, build-script outputs, and workspace incremental states in about two weeks. No intentional cdylib, rlib, or Tauri staticlib target is removed.

[profile.dev]
debug = "line-tables-only"

[profile.dev.package."*"]
debug = false

[profile.debugging]
inherits = "dev"
debug = "full"

One explicit cargo clean removed 20.7 GiB of accumulated workspace artifacts. The representative ordinary rebuild settled at 2.3 GiB; compiling the opt-in full-debug profile brought the complete cache to 3.2 GiB and took 30.5 seconds. Warm Rust verification remains about one second. Ordinary builds retain file-and-line backtraces while avoiding dependency debug data. Incremental compilation remains enabled because its disk use purchases fast rebuilds. If native variable inspection is required, run cargo build --workspace --all-features --profile debugging.

pnpm rust:cache:status reads Cargo metadata, scans without following symbolic links, reports categories, and warns above 10 GiB without failing. pnpm rust:cache:clean delegates deletion to Cargo and is never called by verification. Cleaning is a deliberate exchange: reclaimed disk now for a cold Rust build next time.

This follows Cargo's guidance to reduce development debug information. Cargo documents that incremental compilation stores extra target data to improve recompilation and that the workspace target directory contains both final and intermediate artifacts. Stable automatic global-cache cleanup does not bound workspace target artifacts, so this repository keeps deletion explicit.

Portability and failure boundaries

  • Treat worker numbers as host-specific evidence, not universal constants. Re-measure inside the actual container, VM, WSL distribution, or CI runner because advertised CPUs can exceed sustainable browser capacity.
  • Keep short smoke, sustained single-browser, focused cross-browser, and exhaustive workloads independently tunable. Browser engines and long-lived processes reach different limits.
  • Regenerate browser storage state per invocation beneath ignored output. Treat authentication state as sensitive in other repositories even though this fixture asserts that it contains no cookies and only the local test origin.
  • On Windows, terminate the direct child using native process semantics; on Unix-like hosts, isolate and terminate the complete process group so a failed parallel wave does not leave servers or workers behind.
  • Under WSL, distinguish a runner defect from a host-kernel fault. A process stuck in uninterruptible kernel cleanup cannot be repaired by test retries or SIGKILL; restart WSL before collecting more timing evidence.
  • If Cargo metadata reports a custom target directory, scan and clean that directory through Cargo. A missing target is an empty cache, and symbolic links are never traversed.
  • Accept an optimization only when test assignments, zero retries, tracked artifacts, and failure diagnostics remain intact. Revert it when a repeated target crash, stale UI state, cache invalidation error, or storage/debugging cost outweighs the measured gain.
  • Treat generated bundle size as an implementation signal, not proof of rendering correctness. If a performance refactor changes the direct browser artifact, restore rendering before continuing test work.

Measurement and rollback protocol

  1. Record toolchain, CPU, memory, command, test count, cache state, and working-tree state.
  2. Define the sample count before measuring, report the median and range, and retain failed samples as evidence. Prefer at least three warm samples; this playbook's long full gate used the two samples required by its acceptance plan. Capture a cold sample when changing cache or compiler policy.
  3. Confirm the same tests and browser projects ran. A faster command with less evidence is a coverage change, not a performance result.
  4. Inspect failures at the highest tested concurrency. Fix observable readiness races; lower concurrency only for demonstrated saturation.
  5. Revert a strategy when its stability, memory, debugging, or maintenance cost exceeds the measured wall-time benefit.
