Light-theme Editor presentation

Light mode keeps the Editor canvas warm and neutral while giving Source a distinct #eceae4 background and #dedbd2 gutter. Declaration, field, condition, string, literal, and comment colors are independently darkened for readable syntax contrast. Native Editor scrollbars use the light color scheme. Completion menus, lint tooltips, diagnostic popovers, severity hover states, and the canonical-source Properties note use light surfaces and readable semantic colors. The Add menu, secondary Import action, and saved-project metric rows also remain on neutral light surfaces without dark framing.

These rules are scoped to explicit Light mode. The existing dark Source palette, diagnostics, tooltips, selection geometry, and syntax colors are unchanged. Visual acceptance requires the exact Source, Properties, collapsed/expanded Diagnostics, and error/warning/info hover paths rather than a DOM-only assertion.

Event capture required for every field matrix

Character input, deletion from each edge and middle, select-all, paste, replacement, rapid typing, blur, undo, redo, and tab switching capture source before/after, declaration identity and extent, parsed field names/value ranges, controlled value, preview recovery choice, history entry, and save transition. The invariant is simple: editing one control cannot change or display an adjacent field unless the Format 1 schema explicitly defines that dependency.
