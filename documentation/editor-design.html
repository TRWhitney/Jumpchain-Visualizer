Agreed editor design

Editor properties

The agreed authoring experience for creating valid Jumpchain packages without requiring authors to memorize the markup language. The interactive controls make the accepted behavior concrete and remain implementation references rather than production widgets.

Draft premise: the saved .jdef text remains canonical. Structured controls, raw source, and preview are synchronized views of the same parsed document.

Open the production control and mutation audit for the per-control contract, root-cause evidence, and verification owner.

Agreed behavior

Current editor decisions

Resilient preview

Source updates are debounced while an author types. Invalid source keeps the last valid preview, while deterministic parser recovery may render a safely repaired interpretation with a visible warning.

Interactive preview sandbox

Preview supports the same selections, controls, conditional states, and reactions as the finished browser. Preview choices are temporary and never persist into the user’s chain. Layouts and content rendered through them can expose color-coded node bounds for placement debugging.

Autosave by default

Autosave and recovery are the default. The persistence layer must support a setting that switches to explicit saves if autosave is undesirable or unreliable in a user’s environment.

Automatic file placement

New declarations go to the appropriate package file automatically: jump and sections to jump.jdef, choices to choices.jdef, and jump appearance, layouts, and themes to layout.jdef.

Intent-preserving repair

Low-risk corrections may recover parsing and preview automatically when intent is unambiguous, but source text changes only through Quick Fix or formatting. Ambiguous corrections remain diagnostics with explicit actions.

Package scope

The initial package remains limited to jump.jdef, choices.jdef, layout.jdef, and assets/.

Structured content by default

Selecting semantic content opens Structured. Selecting a physical package file opens Source, because the file itself is the author’s chosen editing target.

Proposed baseline

What the editor needs to do

Foundation

One document, several views

  • Structured editing and source editing share one undo history.
  • Visual actions create minimal, predictable text edits.
  • Formatting is preserved except where the formatter is explicitly invoked.
  • Dirty state, autosave, crash recovery, save, and revert behave consistently.

Navigation

Project and semantic outline

  • Package explorer for jump.jdef, companion files, and assets.
  • Semantic outline for jump appearance, sections, choices, layouts, themes, and traits.
  • Search by name, handle, tag, group, or declaration type.
  • Go to definition, find references, breadcrumbs, and recent locations.

Creation

Guided declaration editing

  • Insert palette for valid declarations at the current location.
  • Context-aware field suggestions, defaults, and constrained value pickers.
  • Purpose-built rich text, image, selection, cost, grant, and layout controls.
  • Keyboard-first creation plus drag reordering where order is meaningful.

Feedback

Preview and diagnostics

  • Debounced live preview with source-to-preview selection synchronization.
  • Errors, warnings, and suggestions inline and in a filterable problems panel.
  • Quick fixes for safe operations; explanations before destructive changes.
  • Preview controls for screen size, theme, rank, properties, and conditional states.

Refactoring

Safe structural changes

  • Rename handles and update all references atomically.
  • Materialize derived handles when references or collisions require stability.
  • Extract choices and layouts into companion files.
  • Detect broken references, duplicate handles, and semantic conflicts.

Assets and access

Human-safe project handling

  • Import, preview, rename, and locate project-relative assets.
  • Require and preview image alternative text.
  • Never discard invalid or unsaved source silently.
  • Full keyboard operation, visible focus, zoom support, and announced diagnostics.

Concept mockup

Adaptive three-pane workspace

Image layout presentation: image leaves are non-text content, so Structured does not expose text align, text size, or text color for them. Size creates a square box, while width and height are independent. Each dimension uses one editable compound control that accepts the discoverable named scale or an exact validated px/rem length. The named image scale doubles from 2rem at xs through 64rem at 2xl. An unsized image uses its intrinsic shrinkable boundary. In Inline and Wrap, Start, Center, and End position that boundary within available row space; Stretch assigns the remaining area to the leaf and lets an unsized image fill it. Explicit dimensions instead remain fixed inside the stretched leaf allocation. The Editor setting Layout preview placeholder length optionally truncates all generated representative layout text to a bounded character count, allowing authors to inspect allocation with shorter content; its blank default preserves complete placeholder strings.

Jump appearance: the singleton entry sits directly below Jump details without its own one-item heading. New projects contain an empty active declaration; Add offers it only while absent and inserts it after leading layout.jdef comments. Structured reuses the established form cards, compound color controls, selectors, diagnostics, and steppers for shared inheritance roots and fine overrides. Its role groups are disclosures that begin expanded and retain the established two-column geometry when open. Empty fields show their resolved inherited swatch without writing it to source; authored colors keep the same status row and display “Manually set value” so paired controls remain aligned. Components is the initial preview mode and uses the real renderer and controls, including a schema-valid bounded integer roll specimen; Jump shows the authored package and Strip color remains transient. Inspect colors is available in both modes and reuses the Show bounds legend, readout, geometry-neutral outlines, hover emphasis, and click navigation. Background, text, border-edge, and accent targets identify their exact configurable color. An authored section or choice layout color is instead marked by the distinct orange Layout override category and names the owning layout, preventing it from being mistaken for appearance inheritance. Clicking an appearance role switches to Structured when necessary, expands its collapsed role group, scrolls the matching field clear of the pane edge, and applies the decaying accent outline without focusing or changing it. Clicking a layout override opens its owning layout and highlights the exact node presentation color by the same path. Placeholder text resolves through Control muted text. The “Example Tag” badge in the specimen demonstrates the user-managed Tag Manager boundary and is excluded from inspection.

The Content view keeps every declaration searchable and groups longer lists into collapsible sections. Its Content/Files tabs and content search remain visible while only the declarations beneath them scroll. Sidebar entries and Structured declaration breadcrumbs use stable declaration handles exclusively, truncate with an ellipsis when space is insufficient, and expose the complete handle as a hover hint. Breadcrumb hierarchy separators have equal spacing on both sides and remain presentation-only for assistive technology. Display names remain reserved for headings and rendered content rather than changing identity paths. Layout and theme declarations use that handle as their sole identity and do not duplicate it with a non-rendered name. A theme entry uses the existing right metadata column for a compact, read-only preview of its validated hex color; invalid or incomplete color source shows no stale swatch, and the preview does not change the row’s handle-only navigation name. While a handle is edited, Structured preserves the selected declaration by its exact source identity; a temporary duplicate reports its diagnostic without navigating to the earlier declaration that currently has the same handle. The root Jump’s Description field is authored package metadata shared by hub cards, previews, and Chain Tracker. Content selections expose both Structured and Source and retain the author’s last choice between them. Entering Files exposes Source only because a package file does not necessarily correspond to one structured declaration; returning to Content restores the retained Content editing view. The Source tab uses the language-aware editing surface documented below, populated with the current selection. Structured uses the same schema context as Source completion: direct choices, selection-dependent controls, grant kinds, references, and layout nodes expose only their applicable fields while invalid authored fields remain repairable. Layout containers are source-ordered structural nodes and do not have handles; the editor derives transient paths from their nested positions for navigation and debugging. The existing Content and declarations card lists an owner’s children in source order, and each row’s leading rail uses the active application accent. Adding a child opens it immediately, focuses its relevant field, and exposes its localized inline diagnostic; a new Image leaves src genuinely unset and lists actual package assets plus Import asset…. That contextual action runs the same bounded picker and validation path as Add → Asset, then atomically adds the file and assigns its relative path without leaving the image block; canceling changes neither source nor assets. Clickable owner breadcrumbs return to the list. Secondary resources remain available through the global Add menu and may also be created and assigned from a cost or grant resource field. Other package-owned references use the same join-in-place model: section, choice, and trait layout fields create and assign the matching top-level layout; direct placements create and assign a canonical choice; token-capable color controls create a theme seeded from the current effective color; and layout text, image, or input targets create content under an explicitly selected compatible owner that actually uses the layout. Each operation commits declaration and reference together, opens the new declaration with a return breadcrumb, and is removed by one Undo. Layout expand nodes also create a referenced choice layout from their using control. Tag strings remain ordinary free-entry package content with no Manage action or Settings link because a user tag profile changes only personal relationships and badge presentation, never whether a tag exists in the Jump. Structured controls show localized shadow text whenever an omitted field resolves to an effective format default and the control would otherwise be empty, including contextual starting-point and companion-input values. Dropdowns instead display their ordinary effective value without a duplicate Default: entry, and choosing that value restores source omission. Layout references name their built-in section, choice, or trait fallback; required format remains blank when omitted because omission is a diagnostic rather than a default. A boolean shadow label returns whenever toggling restores its omitted default state. The preview stays contextual to the current selection. Selecting a layout renders that layout through the canonical renderer with localized representative data for every authored slot, text, image, input, expanded choice source, direct choice, or trait target; this isolated authoring fixture remains available when unrelated package diagnostics would otherwise force a last-valid package fallback and never enters project source or saved state. Strip color sits beside Show bounds and removes authored layout backgrounds, text colors, rule colors, and theme resolution only from the current preview. It is transient editor UI state and never changes source, history, or saved project data. When the current preview is a layout or uses one, Show bounds reveals mock-matched cyan dashed containers, green solid slots, and purple dotted content references around the populated preview data. The compact localized readout remains directly below the legend and above the preview. Hovering changes only the exact inspected boundary to a two-pixel solid line and identifies its category and derived structural path; ancestors retain their ordinary line treatment. While a layout is selected, clicking that exact boundary navigates the active authoring view: Structured switches to the owning container in one action, keeps presentation disclosures collapsed, scrolls the node into view, and briefly fades an outline around it without focusing an editable control; Source selects only the parsed declaration keyword or compact field tag on its authored line. Bounds are geometry-neutral: the authored preview surface and its package colors remain limited to rendered content rather than expanding into otherwise unused pane space. A compact diagnostics strip remains available at the bottom, previews the highest-priority problem, and opens its scrollable details upward without changing the mockup height.

Assets remain first-class image files with an isolated authoring document rather than source declarations. The Assets group renders nested asset folders in Content and Files, labels leaves by basename, and shows each byte-signature-derived canonical extension. Content assets now expose both Structured and Source, remember their authoring tab independently from declarations, and keep the right Preview visible while Source performs a distinct editing job. Their read-only Properties view supplements format, dimensions, and byte size with bounded allowlisted header details when available: color model and bit depth, encoding or interlace, alpha and animation flags, color profile, pixel density, EXIF orientation, GIF version, and palette size. It does not surface arbitrary comments, text chunks, camera information, author data, or GPS fields. A persistent Local copy badge makes the boundary explicit: autosave and recovery retain flattened bytes plus editor-only SVG drafts or raster layers, while imported archives and desktop source-folder assets remain byte-identical. Explicit .jmp export validates and emits only flattened image bytes, never the layered document. Rename, Trash, Restore, undo, redo, and permanent deletion move the sidecar atomically with its asset.

SVG Source is a secure XML editor whose typography, gutter, active-line rail, selections, folding, and dark/light surfaces match the declaration Source editor. CodeMirror’s Lezer XML grammar supplies context-aware SVG element completion plus distinct tag, attribute, string, bracket, processing-instruction, comment, and invalid-token highlighting. Validation settles after 300 ms; valid authored text is retained byte-for-byte and updates Preview, while malformed XML, active elements, event handlers, entities, external links, active CSS, and over-budget geometry preserve an invalid draft without replacing the last valid preview. PNG and JPEG use a non-destructive raster workspace: a compact command bar, 32-pixel tool rail, centered checkerboard proxy, collapsible contextual inspector, and persistent Layers panel. Corrections are rebuilt from the immutable base with the same pixel math in the interaction canvas and flattened Preview; markup is composited afterward and is never color-corrected. Slider values remain draggable but can also be clicked for exact numeric entry or reset individually; presets reset the correction set before applying their named values. Full-resolution commits run after gesture completion through a cancellable bundled worker and Pica’s deterministic tiled resize; only the latest render and package validation generation may commit. APNG, GIF, WebP, and AVIF remain concise read-only states.

Paint and eraser gestures render continuously under the pointer and commit one undoable gesture when the pointer is released. Paint creates one independently selectable layer per stroke. Eraser creates no visible layer of its own: it stores a reversible mask on each intersected, visible, unlocked markup layer, leaving locked layers intact and revealing the corrected base beneath erased pixels. Paint groups use their own local bounding-box origin, so dragging applies the requested document delta and resizing keeps the opposite bounds stable instead of scaling around the image origin. Selection handles and object dragging exist only in Select, so beginning a paint, eraser, shape, text, line, arrow, or crop gesture cannot move existing artwork. A text drag sets its initial box width and font size from the drawn bounds; later side-handle transforms change the box width without scaling glyphs. Text, line, arrow, rectangle, ellipse, and crop tools begin on the image and use the drag bounds rather than creating defaults from the tool rail. Layers can be renamed by double click; hidden or locked layers expose no transform handles, and paint bounds have numeric position and size controls. All raster numeric inputs reuse the property editor’s always-visible, thin SVG increment/decrement steppers instead of browser-native hover-only arrows. Pan scrolls only the viewport, never the asset transform; holding the middle mouse button temporarily selects Pan and restores the previous tool on release without changing pointer-to-image coordinates. Show Original is a stable toggle that temporarily shows the immutable base without corrections or markup. Hover/focus tooltips are fixed overlays that never resize the panel and are dismissed before their target disappears. Standard undo/redo works while the canvas has focus, and Select, Pan, Crop, Paint, Eraser, Text, Line, Arrow, Rectangle, and Ellipse shortcuts are configurable in collapsible Key Binding groups. Every canvas operation retains an equivalent semantic control, and the inspector becomes an in-component overlay at narrow widths without altering the outer editor grid.

Asset rejection feedback: Add → Asset keeps the existing notification surface but names the one rule that rejected the selection. Extension, configured byte limit, safe path, duplicate location, byte signature, decode, PNG integrity, trailing data, decoded geometry, dimension consistency, read, and unexpected validation failures use distinct localized events; a rejected selection never mutates the workspace.

Guided conditional values: conditional renderable fields retain the existing field card and add source-ordered, individually railed variant cards below the base value. A concise localized summary explains that the first matching variant replaces that field and that the base value remains the fallback. Adding a variant begins as a transient property draft, so no synthetic when true line enters Source. Property, operator, and typed value controls share the validator’s engine/context/package property catalog. Add condition adds another comparison to the current All/Any group; Add nested group creates a subgroup with independent All/Any and inversion controls. Builder and compact Expression modes preserve authored syntax until an actual guided edit occurs. Variant value labels repeat the base field label—Content, Name, Alt, or Option—rather than the generic word Value. Only the editor pane scrolls as variants and drafts grow; the application route never gains a second page scrollbar.

Top-level declaration and asset leaves use the shared application context menu for localized Open/Delete actions. Top-level disclosure headers use the same implementation: Resources, Sections, Choices, Themes, and Assets offer their matching Add action above the current Expand or Collapse action; Layouts offers Section, Choice, and Trait layout additions; Trash exposes only disclosure control. Pointer and keyboard invocation share measured viewport placement, theme and RTL styling, menu focus behavior, and dismissal. Header additions run through the same command as the retained toolbar Add menu, including immediate selection, focus, announcement, and history behavior. By default, Delete moves the exact declaration source or asset bytes into the editor-owned Trash and removes the item from live package source or assets; Trash never enters export or external project files. The off-by-default Editor preference editor.permanentlyDeleteSidebarItems instead routes Delete directly through the shared permanent-deletion confirmation. While enabled, an empty Trash disclosure disappears from Content and Files, but any existing trashed entries keep it visible and recoverable. Trash otherwise appears as the final disclosure in both sidebars and preserves exclusive selection. Deleted declarations show only their captured declaration in a read-only Source pane, while deleted assets retain the read-only image surface. A trashed item’s menu offers Open, Restore, and Delete. Restore appends declarations to their original definition file or returns assets to their original path when that location remains available. Either permanent Delete path uses the same shared application confirmation dialog as chain and project deletion, then clears undo/redo history so deleted source and bytes cannot be recovered. Ordinary move-to-Trash and restore remain atomic undoable workspace commands. Structured layout rows and raster layers also expose the exact visible move, presentation, selection, rename, visibility, lock, duplicate, and removal commands catalogued by the audit.

Structured content selections keep the Preview scoped to the closest useful rendered subject instead of returning to the complete Jump. Section text retains its enclosing section preview, an image block isolates its resolved asset, a section-owned direct choice renders its target choice, and a choice source renders exactly the choices matched by that source. Other choice-owned content retains its enclosing choice preview. When the default-on Accessibility preference is enabled, hovering an image in either its isolated image-block preview or a containing section/choice/trait layout reveals the active authored alternative text without altering the image geometry; empty alternative text adds no visual tooltip. Disabling the visual hover copy does not remove the image's authored alternative text or its accessibility semantics.

The layout card’s interaction is container-focused: authors select or open a container, follow its structural-path breadcrumb, edit flow and presentation, then work with its direct children in source order. The editor remembers the active container independently for each structured layout while the workspace is open, so sidebar work on another declaration does not reset the layout to its root. The same presentation icon beside the active container controls and on eligible child rows toggles both forms consistently; no separate compact-form button is introduced. Expanded child presentation forms take their complete natural height and rely on the Structured pane’s existing scrollbar rather than introducing a nested scroll region. Changing the active container collapses any open child presentation form, and reparenting through either drag or Move… also leaves the moved child collapsed in its destination. Arrows and drops at a row’s top or bottom edge reorder siblings. Every enabled input, select, textarea, button, editable region, and compound widget inside a draggable child row is an interaction boundary: selecting text or operating the control cannot start a row drag, while the drag handle and non-control row surface retain the established movement behavior. Package handle references use one uninterrupted editable dropdown: authors may type a future handle, choose an existing handle filtered to the schema-compatible declaration kind, or choose the final New … row to create and assign one. No separate plus button changes the row’s geometry, and an omitted built-in fallback remains shadow text. Dropping into the highlighted center of a valid container row reparents the node; Move… provides the equivalent accessible operation and every legal destination. The Move button toggles those controls open and closed, without a redundant Cancel action. Bounded integer presentation fields such as Grid Columns and Rule Thickness use the Editor’s established paired-chevron stepper rather than a browser-native spinner; omitted defaults supply the effective stepping baseline without becoming authored source. Color presentation uses one uninterrupted normal-width compound field: its leading live swatch opens the native picker, its center accepts six-digit hex or tokens, and its standard editor chevron opens a small bounded swatch grid for built-in and package-theme choices whose final compact row is New Theme…. A hex-only theme color uses that same trailing segment for a dropper icon when screen sampling is available; a successful sample becomes one canonical hex edit, cancellation is inert, and unsupported environments hide the action. Browser and Windows WebView2 builds use the user-activated EyeDropper API, while Linux desktop builds use the XDG screen-color portal without exposing continuous screen data. The picker and token grid close one another so only one color chooser is open, and each dropdown overlays rather than reflows the layout card. Picker movement updates the compound field locally and coalesces into one authored source/history update when movement settles or the picker closes, avoiding repeated document parsing while the native color area tracks the pointer. Compound fields are also interactive drag boundaries: selecting their text or operating a chooser never starts a parent layout-row reorder. Container Align follows the selected flow’s cross-axis. Inline and Wrap keep unstretched children at a bounded content width: Start, Center, and End position those boundaries in available row space, while Stretch grows into the remainder. Multiple stretched siblings divide that remainder equally after unstretched content keeps its space. Text, slot, and input boundaries retain enough internal width for Text Align to move their contents independently. Stack and Grid use their corresponding available horizontal area. Text align is inherited from containers and can be overridden per text-bearing leaf; padding, background, and Align apply to every leaf boundary, while text alignment, size, and color apply only to rich text, slots, and inputs—not images. Unsized images preserve a visible shrinkable boundary in every flow. Deleting a container promotes its children, and Add child lists only schema-legal nodes and gathers required targets in a baseline-aligned row whose node type, target dropdown, and Add child button share one control height. The mock defines this geometry and interaction while the Format 1 schema supplies the complete section, choice, and trait capability sets.

Source authoring draft

Language-aware source editor

Source editing should feel like a purpose-built language tool, not a plain text area. Folding, resilient preview, find, inline completion, Quick Fix, and the context palette below are interactive.

Editing essentials

Line numbers, declaration and block folding, syntax highlighting, indentation guides, auto-indentation, ⌘ F search and replace, multi-cursor editing, and durable undo/redo. Find opens as one compact row: a rounded field contains subdued gray Aa, ab, and .* toggles that brighten when active, followed by previous/next arrows, the current-match count, and a Replace checkbox. Replace remains collapsed until requested, then adds one row with its rounded field and both replacement actions inline. Up and Down in either text field perform the same wrapping navigation as the visible arrow controls; the Find and Replace placeholder text remains visible when each entry is empty. A narrow accent bar at the code edge identifies the cursor line or the lines crossed by a selection; it never fills the line. The insertion caret and the exact selected text remain separate, unmistakable states. A single restrained gutter chevron communicates each fold state; folded text adds no ellipsis pill or duplicate inline arrow.

Language intelligence

Contextual ghost text accepted with Tab, a full ⌘ Space completion list, field and token documentation, handle suggestions, definitions, references, safe rename, symbols, and formatting. ⌘ Space toggles the completion list; when invoked from Quick Add, the list overlays the palette so closing it returns to the same context. ⌘ Enter likewise toggles Quick Add. Quick Add selects the inserted value at its natural editing point and exposes collision-free, underlined letter mnemonics for Valid-here actions, displayed with the primary-modifier icon before the letter.

Diagnostics and preview

Inline errors and warnings, preview-only deterministic recovery, ⌘ . Quick Fix source edits, explicit actions for ambiguous fixes, debounced parsing, and a clearly marked last-valid or safely recovered preview. A missing declaration field underlines only that declaration’s keyword; its hover details use the editor’s dark diagnostic surface rather than painting the whole block or opening a light tooltip.

Completion is narrow by default

Ghost text shows only the highest-ranked valid suggestion. It considers file role, enclosing declaration, indentation, cursor position, fields already present, repeatability, valid values, and package handles. Tab accepts it only while visible; otherwise Tab indents normally.

One context palette

⌘ Enter opens a palette for the cursor location. It replaces a separate cheat sheet by listing valid fields and child declarations together with relevant editor commands. Empty required fields already present in source remain listed as completion targets and select their existing editable value rather than inserting a duplicate. Every entry and each Source-toolbar command displays its effective accelerator, preserving fast keyboard-oriented insertion without requiring authors to memorize hidden shortcuts.

Recovery does not rewrite

Safe parser recovery may keep preview current, but it does not silently change source or move the cursor. Quick Fix commits a deterministic repair; formatting may commit all outstanding deterministic repairs. All defaults are rebindable and displayed using platform-appropriate key labels.

Implementation contract

Hub, recovery, and secure package transport

One source-authoritative workspace

The production Editor implements this mock’s Content/Files, Structured/Source, and Preview/Properties panes with one package-wide history. Browser workspaces persist in IndexedDB; desktop folders remain canonical and use atomic replacement plus an application-data recovery mirror. The operational Open Project Folder action is hidden by default and can be exposed from Developer settings. Invalid authored source is retained while preview uses deterministic recovery or the last valid package.

The real renderer owns preview

Package, section, choice, and layout preview scopes use the same canonical renderer and disposable evaluator as Chain Tracker. Show Bounds annotations are geometry-neutral, use fixed semantic debug colors, and never inherit the application accent.

Portable packages cross one security gate

Editor import and Chain installation stage and validate an entire .jmp before creating anything. Reviews show identity, version, content hash, counts, diagnostics, and effective limits. Authoring warnings require an explicit Import Anyway; security, integrity, schema, missing-asset, unsupported-format, and limit failures cannot be overridden.

Research notes

Why these properties are on the table

Language-aware editing is a bundle, not syntax highlighting

Established editor APIs group diagnostics, completion, hover, definitions, references, symbols, formatting, folding, and code actions. The Jumpchain language service should expose one semantic implementation that every editor view can reuse.

VS Code programmatic language features · Monaco inline completion · CodeMirror completion context

Hybrid editors need one authoritative model

VS Code's custom-editor guidance recommends minimal text edits, synchronization in both directions, protection against update loops, and graceful handling of temporarily invalid structured text. Those requirements apply directly to synchronized form/source editing.

VS Code Custom Editor API

Error-tolerant parsing is part of the editing experience

Incremental parser systems represent unrecognized and missing input explicitly, allowing diagnostics and surrounding structure to survive while a user is halfway through an edit.

Tree-sitter error and missing nodes

Projectional editing solves validity but introduces interaction risk

Direct AST editors can guarantee structure and present specialized controls, but established projectional-editor documentation acknowledges that deletion behavior can be difficult to predict. A hybrid approach should use familiar form controls and always retain a source escape hatch.

JetBrains MPS projectional editing · JetBrains MPS editor behavior

Project navigation must be intentionally keyboard-accessible

Tree and grid widgets bring specific focus-management and arrow-key obligations. We should prefer simpler disclosure navigation until the project explorer truly needs full tree behavior.

WAI-ARIA tree view pattern · WAI-ARIA grid pattern

Local project access needs a fallback

Browser file and directory handles require explicit user permission and are not uniformly available. The product should support both direct folder access where available and portable import/export everywhere else.

MDN File System API
