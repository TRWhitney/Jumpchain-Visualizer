Agreed editor design

Editor properties

The agreed authoring experience for creating valid Jumpchain packages without requiring authors to memorize the markup language. The interactive controls make the accepted behavior concrete and remain implementation references rather than production widgets.

Draft premise: the saved .jdef text remains canonical. Structured controls, raw source, and preview are synchronized views of the same parsed document.

Open the production control and mutation audit for the per-control contract, root-cause evidence, and verification owner.

Agreed behavior

Current editor decisions

Resilient preview

Source updates are debounced while an author types. Invalid source keeps the last valid preview, while deterministic parser recovery may render a safely repaired interpretation with a visible warning.

Interactive preview sandbox

Preview supports the same selections, controls, conditional states, and reactions as the finished browser. Preview choices are temporary and never persist into the user’s chain. Layouts and content rendered through them can expose color-coded node bounds for placement debugging.

Autosave by default

Autosave and recovery are the default. The persistence layer must support a setting that switches to explicit saves if autosave is undesirable or unreliable in a user’s environment.

Automatic file placement

New declarations go to the appropriate package file automatically: jump and sections to jump.jdef, choices to choices.jdef, and layouts and themes to layout.jdef.

Intent-preserving repair

Low-risk corrections may recover parsing and preview automatically when intent is unambiguous, but source text changes only through Quick Fix or formatting. Ambiguous corrections remain diagnostics with explicit actions.

Package scope

The initial package remains limited to jump.jdef, choices.jdef, layout.jdef, and assets/.

Structured content by default

Selecting semantic content opens Structured. Selecting a physical package file opens Source, because the file itself is the author’s chosen editing target.

Proposed baseline

What the editor needs to do

Foundation

One document, several views

  • Structured editing and source editing share one undo history.
  • Visual actions create minimal, predictable text edits.
  • Formatting is preserved except where the formatter is explicitly invoked.
  • Dirty state, autosave, crash recovery, save, and revert behave consistently.

Navigation

Project and semantic outline

  • Package explorer for jump.jdef, companion files, and assets.
  • Semantic outline for sections, choices, layouts, themes, and traits.
  • Search by name, handle, tag, group, or declaration type.
  • Go to definition, find references, breadcrumbs, and recent locations.

Creation

Guided declaration editing

  • Insert palette for valid declarations at the current location.
  • Context-aware field suggestions, defaults, and constrained value pickers.
  • Purpose-built rich text, image, selection, cost, grant, and layout controls.
  • Keyboard-first creation plus drag reordering where order is meaningful.

Feedback

Preview and diagnostics

  • Debounced live preview with source-to-preview selection synchronization.
  • Errors, warnings, and suggestions inline and in a filterable problems panel.
  • Quick fixes for safe operations; explanations before destructive changes.
  • Preview controls for screen size, theme, rank, properties, and conditional states.

Refactoring

Safe structural changes

  • Rename handles and update all references atomically.
  • Materialize derived handles when references or collisions require stability.
  • Extract choices and layouts into companion files.
  • Detect broken references, duplicate handles, and semantic conflicts.

Assets and access

Human-safe project handling

  • Import, preview, rename, and locate project-relative assets.
  • Require and preview image alternative text.
  • Never discard invalid or unsaved source silently.
  • Full keyboard operation, visible focus, zoom support, and announced diagnostics.

Concept mockup

Adaptive three-pane workspace

The Content view keeps every declaration searchable and groups longer lists into collapsible sections. Its Content/Files tabs and content search remain visible while only the declarations beneath them scroll. Sidebar entry names truncate with an ellipsis when space is insufficient and expose the complete name as a hover hint. The root Jump’s Description field is authored package metadata shared by hub cards, previews, and Chain Tracker. Content selections expose both Structured and Source and retain the author’s last choice between them. Entering Files exposes Source only because a package file does not necessarily correspond to one structured declaration; returning to Content restores the retained Content editing view. The Source tab uses the language-aware editing surface documented below, populated with the current selection. The preview stays contextual to the current selection. When the current preview is a layout or uses one, Show bounds reveals color-coded containers, slots, and content references around the populated preview data; hovering one boundary identifies it in the debugger readout without covering the content. Bounds are geometry-neutral: the authored preview surface and its package colors remain limited to rendered content rather than expanding into otherwise unused pane space. A compact diagnostics strip remains available at the bottom, previews the highest-priority problem, and opens its scrollable details upward without changing the mockup height.

Source authoring draft

Language-aware source editor

Source editing should feel like a purpose-built language tool, not a plain text area. Folding, resilient preview, find, inline completion, Quick Fix, and the context palette below are interactive.

Editing essentials

Line numbers, declaration and block folding, syntax highlighting, indentation guides, auto-indentation, ⌘ F search and replace, multi-cursor editing, and durable undo/redo. Find opens as one compact row: a rounded field contains subdued gray Aa, ab, and .* toggles that brighten when active, followed by previous/next arrows, the current-match count, and a Replace checkbox. Replace remains collapsed until requested, then adds one row with its rounded field and both replacement actions inline. Up and Down in either text field perform the same wrapping navigation as the visible arrow controls; the Find and Replace placeholder text remains visible when each entry is empty. A narrow accent bar at the code edge identifies the cursor line or the lines crossed by a selection; it never fills the line. The insertion caret and the exact selected text remain separate, unmistakable states. A single restrained gutter chevron communicates each fold state; folded text adds no ellipsis pill or duplicate inline arrow.

Language intelligence

Contextual ghost text accepted with Tab, a full ⌘ Space completion list, field and token documentation, handle suggestions, definitions, references, safe rename, symbols, and formatting. ⌘ Space toggles the completion list; when invoked from Quick Add, the list overlays the palette so closing it returns to the same context. ⌘ Enter likewise toggles Quick Add. Quick Add selects the inserted value at its natural editing point and exposes collision-free, underlined letter mnemonics for Valid-here actions, displayed with the primary-modifier icon before the letter.

Diagnostics and preview

Inline errors and warnings, preview-only deterministic recovery, ⌘ . Quick Fix source edits, explicit actions for ambiguous fixes, debounced parsing, and a clearly marked last-valid or safely recovered preview. A missing declaration field underlines only that declaration’s keyword; its hover details use the editor’s dark diagnostic surface rather than painting the whole block or opening a light tooltip.

Completion is narrow by default

Ghost text shows only the highest-ranked valid suggestion. It considers file role, enclosing declaration, indentation, cursor position, fields already present, repeatability, valid values, and package handles. Tab accepts it only while visible; otherwise Tab indents normally.

One context palette

⌘ Enter opens a palette for the cursor location. It replaces a separate cheat sheet by listing valid fields and child declarations together with relevant editor commands. Empty required fields already present in source remain listed as completion targets and select their existing editable value rather than inserting a duplicate. Every entry and each Source-toolbar command displays its effective accelerator, preserving fast keyboard-oriented insertion without requiring authors to memorize hidden shortcuts.

Recovery does not rewrite

Safe parser recovery may keep preview current, but it does not silently change source or move the cursor. Quick Fix commits a deterministic repair; formatting may commit all outstanding deterministic repairs. All defaults are rebindable and displayed using platform-appropriate key labels.

Implementation contract

Hub, recovery, and secure package transport

One source-authoritative workspace

The production Editor implements this mock’s Content/Files, Structured/Source, and Preview/Properties panes with one package-wide history. Browser workspaces persist in IndexedDB; desktop folders remain canonical and use atomic replacement plus an application-data recovery mirror. The operational Open Project Folder action is hidden by default and can be exposed from Developer settings. Invalid authored source is retained while preview uses deterministic recovery or the last valid package.

The real renderer owns preview

Package, section, choice, and layout preview scopes use the same canonical renderer and disposable evaluator as Chain Tracker. Show Bounds annotations are geometry-neutral, use fixed semantic debug colors, and never inherit the application accent.

Portable packages cross one security gate

Editor import and Chain installation stage and validate an entire .jmp before creating anything. Reviews show identity, version, content hash, counts, diagnostics, and effective limits. Authoring warnings require an explicit Import Anyway; security, integrity, schema, missing-asset, unsupported-format, and limit failures cannot be overridden.

Research notes

Why these properties are on the table

Language-aware editing is a bundle, not syntax highlighting

Established editor APIs group diagnostics, completion, hover, definitions, references, symbols, formatting, folding, and code actions. The Jumpchain language service should expose one semantic implementation that every editor view can reuse.

VS Code programmatic language features · Monaco inline completion · CodeMirror completion context

Hybrid editors need one authoritative model

VS Code's custom-editor guidance recommends minimal text edits, synchronization in both directions, protection against update loops, and graceful handling of temporarily invalid structured text. Those requirements apply directly to synchronized form/source editing.

VS Code Custom Editor API

Error-tolerant parsing is part of the editing experience

Incremental parser systems represent unrecognized and missing input explicitly, allowing diagnostics and surrounding structure to survive while a user is halfway through an edit.

Tree-sitter error and missing nodes

Projectional editing solves validity but introduces interaction risk

Direct AST editors can guarantee structure and present specialized controls, but established projectional-editor documentation acknowledges that deletion behavior can be difficult to predict. A hybrid approach should use familiar form controls and always retain a source escape hatch.

JetBrains MPS projectional editing · JetBrains MPS editor behavior

Project navigation must be intentionally keyboard-accessible

Tree and grid widgets bring specific focus-management and arrow-key obligations. We should prefer simpler disclosure navigation until the project explorer truly needs full tree behavior.

WAI-ARIA tree view pattern · WAI-ARIA grid pattern

Local project access needs a fallback

Browser file and directory handles require explicit user permission and are not uniformly available. The product should support both direct folder access where available and portable import/export everywhere else.

MDN File System API
