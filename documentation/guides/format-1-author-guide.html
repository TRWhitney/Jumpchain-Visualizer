Author reference

Format 1 Author Guide

This guide teaches the complete Format 1 language used to build editable .jmp packages. Start with the tutorial, then use the generated syntax tables as a field reference.

Create a package

A Format 1 package contains definition files at its root and graphical assets under assets/. 

jump.jdef       required metadata, Sections, and optionally Choices and layouts
choices.jdef    optional top-level Choices
layout.jdef     optional appearance, themes, and layouts
assets/         referenced PNG, JPEG, GIF, WebP, AVIF, or SVG files

Definitions use UTF-8, LF line endings, two-space indentation, and full-line comments beginning with #. Tabs are errors. A declaration begins at the left edge, fields use name: value, and child declarations are indented beneath their owner.

Write the smallest Jump

jump
  format: 1
  name: "First Jump"
  author: "Example Author"
  version: "1.0"

section
  handle: introduction
  name: "Introduction"

Every package needs exactly one jump and at least one section. Quoted values are displayed to the User. Bare values are structural tokens or handles.

Use handles and references

A handle identifies a declaration. Write handles in lowercase snake case, such as physical_fitness. References may point forward to declarations defined later or in another definition file.

Keep handles stable. Renaming a handle changes the identity used by layouts, saved selections, grants, conditions, and other references.

Describe the Jump

jump
  format: 1
  name: "Skybound"
  description: "A ten-year adventure among floating islands."
  author: "A. Author"
  author: "B. Author"
  version: "2.1"
  gauntlet: false
  starting-points: 1000
  points-name: "Choice Points"
  points-abbreviation: "CP"
  discount-stacking: highest
  discount-floor: zero
  section-layout: standard_section
  choice-layout: standard_card
  trait-layout: local_trait

starting-points configures the built-in jump_points resource. A Jump may name default Section, Choice, and Trait layouts. Individual declarations can select a different layout.

Add another resource

resource
  handle: mana
  name: "Mana"
  abbreviation: "MP"
  initial: 25

Costs and grants refer to the resource handle. Omit the resource on a cost or resource grant to use jump_points.

Grant unconditional content

Place grant children directly under jump when everyone receives something without making a selection. 

jump
  format: 1
  name: "Skybound"
  author: "A. Author"
  version: "2.1"

  grant
    kind: item
    name: "Travel Pack"

  grant
    kind: trait
    name: "Ten-Year Stay"

    text
      handle: description
      content: "This circumstance lasts for the current Jump."

Jump-level property grants require an explicit value because they do not own a control.

Organize Sections and Choices

section
  handle: perks
  name: "Perks"
  layout: perk_section

  text
    handle: introduction
    content: "Choose the abilities you want."

  choice-source
    handle: perk_choices
    group: perks
    mode: multi
    max: 4

  choice
    handle: featured
    target: signature_move

A Section can own Text and Image content, Choice Sources, and direct Choice placements. A direct placement points to one top-level Choice and has its own Section-local handle for layout targeting.

Set selection behavior

A Choice Source gathers top-level Choices that share its group.

  • mode: single permits zero or one active Choice.
  • mode: multi permits any number unless max is present.
  • resolution: random uses a roll rather than manual selection.
  • resolution: either allows rolling or manual selection.

A maximum never creates a required or default selection.

Lock Sections

section
  handle: advanced_training
  name: "Advanced Training"
  locked: 3

choice
  handle: academy_access
  name: "Academy Access"
  unlock: advanced_training

locked sets an initial count from 0 through 5; zero and omission both start the Section unlocked. Each active lock adds one lock and each active unlock removes one. The Section remains locked while the total is greater than zero. Existing selections are preserved while locked, but their ordinary costs, grants, and effects are suspended.

Author Choices and controls

choice
  handle: flight
  name: "Flight"
  group: perks
  tag: mobility
  selection: toggle

  text
    handle: description
    content: "Fly under your own power."

  cost: 200
  grant: perk

A top-level Choice defines content and behavior. A Section displays it through a matching Choice Source or a direct placement.

Choose a selection mode

Mode Use Important fields
toggle On or off purchase No value fields
text Free-form answer placeholder
integer Bounded number or repeated ranks min, max, resolution, measure
select One value from repeated options option, continuity, resolution
companions Select Companion owners min, max, placeholder

Use options and continuity

choice
  handle: starting_gender
  name: "Starting gender"
  group: identity
  selection: select
  continuity: previous
  option: "Female"
  option: "Male"
  option: "Nonbinary"

  grant
    kind: property
    handle: gender

Continuity can preserve the previous or original value. It does not constrain which options an author may provide. Conditions may vary an option while retaining its base option association.

Use integers and rolls

choice
  handle: age
  name: "Age"
  selection: integer
  min: 10
  max: 17
  resolution: either

  cost: 100

  grant
    kind: property
    handle: age

With either, a rolled result can use its roll allowance while a manual result pays the authored cost. Integer grants use measure: rank for ranked perks and measure: quantity for repeated items.

Add owner-local inputs

choice
  handle: starter
  name: "Starter Pokémon"
  selection: text
  placeholder: "Enter a species"

  input
    handle: nickname
    selection: text
    placeholder: "Optional nickname"

  grant
    kind: companion
    handle: starter_companion
    name: "{starter} (Starter Pokémon)"

Inputs belong to their Choice and use owner-local handles. Renderable strings may interpolate the owning Choice answer and its input answers.

Set costs and discounts

choice
  handle: master_ball
  name: "Master Ball"
  group: gear
  selection: integer
  min: 0
  measure: quantity

  cost
    resource: jump_points
    amount: 100
    mode: each

  grant
    kind: item
    name: "Master Ball"
    measure: quantity

Cost shorthand such as cost: 100 uses Jump Points. A cost block can name another resource and select whether the amount is paid once or for each integer rank.

Grant group discounts

choice
  handle: engineer_origin
  name: "Engineer"
  group: origins

  discount
    group: technology
    mode: flat
    amount: 100

  discount
    group: skills
    mode: percent
    amount: 50
    resource: jump_points

A discount targets a Choice group. Omit resource to affect every resource. Under highest stacking, the best matching effect wins. Under stack, flat discounts apply first, then percentages are added and applied once. discount-floor: zero prevents negative payable costs; negative permits them.

Grant content

Grants may belong to the Jump, a Choice, or an Input. Use a block when you need names, descriptions, ownership, quantities, or handles. 

choice
  handle: bonded_weapon
  name: "Bonded Weapon"

  grant
    kind: item
    handle: bonded_blade
    name: "Bonded Blade"
    tag: weapon

    text
      handle: description
      content: "A weapon that returns when called."

  cost: 200

Choose a grant kind

  • perk adds a durable ability.
  • item adds a durable possession.
  • form adds an alternate form.
  • companion adds a Companion.
  • trait adds a current-Jump circumstance.
  • resource changes a resource balance.
  • property writes an identity or other scalar property.

Target Forms and Companions

choice
  handle: dragon_scales
  name: "Dragon Scales"

  grant
    kind: perk
    name: "Armored Scales"
    form: dragon_form

choice
  handle: mental_bond
  name: "Mental Bond"

  grant
    kind: perk
    name: "Mental Bond"
    companion: starter_companion

form and companion target an existing grant handle. A grant cannot have conflicting owners. Companion selection can also assign purchases to selected Companions.

Use Traits for local circumstances

A Trait belongs only to the current Jump. Use it for backgrounds, local legal status, drawbacks, temporary setting effects, and Jump terms. Do not use a Trait for an ability or possession that remains in later Jumps.

Write properties

A property grant uses its handle as the property name. A Choice or Input can supply the value. A Jump-level property grant must specify value as a quoted string, integer, or Boolean.

Write text, conditions, and Tags

Use a quoted scalar for a short value and a triple-quoted body for paragraphs, lists, and tables. 

text
  handle: description
  content:
    """
    A short opening paragraph.

    - First effect
    - Second effect\
      with a deliberate hard break

    **Bold**, *italic*, ~~struck~~, and underlined text are supported.
    """

A trailing backslash creates a hard line break. Raw HTML, links, headings, blockquotes, task checkboxes, and code blocks are not supported inside rich text.

Vary renderable values

text
  handle: description
  content: "You receive one charge."
  content when rank > 1: "You receive {rank} charges."

Conditional variants are available on name, alt, content, and option. Use !, comparisons, parentheses, and, and or. The first matching variant wins; the base value is the fallback.

Add Tags

choice
  handle: wings
  name: "Wings"
  tag: mobility
  tag: flight

Tags are author-provided strings used for filtering and organization. The User's active Tag profile always controls badge colors, borders, shapes, typography, hierarchy, and animation. Layouts may place the Tags slot but cannot style Tag text or badges. Cost badges are separate from Tags.

Set appearance and themes

theme
  handle: cyan
  color: "#00ffff"

jump-appearance
  background: "#404040"
  text-color: cyan
  accent-color: cyan
  surface-background: "#404040"
  surface-text: cyan
  corners: none
  canvas-padding: sm
  section-spacing: md

A Theme names a reusable color. Jump appearance fields configure semantic application surfaces, including the canvas, header, budget, Sections, Choices, groups, controls, costs, tooltips, spacing, corners, and structural border width. Use hex colors or built-in color tokens where the field accepts a color.

Build layouts

Layouts separate reusable composition from semantic content. A Section, Choice, or Trait layout contains exactly one root Stack, Inline, Wrap, or Grid. 

choice-layout
  handle: ability_card

  stack
    gap: sm
    padding: md

    inline
      justify: between
      align: start
      slot: name
      slot: cost

    text: description

    inline
      justify: between
      align: center
      slot: tags
      slot
        target: control
        control-density: compact

Choose a container

  • stack arranges children vertically.
  • inline arranges children horizontally with a shared row extent.
  • wrap arranges children in wrapping rows.
  • grid arranges children in declared columns and responsive tracks.

Containers accept presentation fields for gaps, padding, alignment, justification, background, border, dimensions, and related geometry. An optional grow on a direct child allocates available Stack or Inline space by weight.

Use Grid tracks and spans

grid
  columns: 3
  column-weight: 3
  column-weight: 4
  column-weight: 2
  gap: md

  choice
    target: featured
    column-span: 2

  expand
    source: remaining
    using: ability_card

Provide one column-weight for every column or omit all weights for equal tracks. Children may span rows or columns. At narrow widths, authored tracks and spans collapse to preserve source order and prevent horizontal overflow.

Place content and slots

  • slot places semantic fields such as name, cost, control, roll, and tags.
  • text, image, and input target owner-local handles.
  • rule draws a horizontal or vertical separator.
  • choice places one direct Section Choice.
  • expand places every member of a Choice Source, optionally through a named Choice layout.

Compact shorthand such as slot: cost is equivalent to a block with target: cost. Use a block to add presentation fields.

Control spacing and sizing

Use spacing tokens from none through 2xl. Axis-specific padding-block and padding-inline override the corresponding axis from padding. Minimum dimensions and image dimensions accept bounded tokens, pixels, or rem values. Use aspect-ratio such as 16/9 when the source demonstrates a stable ratio.

Set typography

text
  target: description
  font-family: condensed
  font-weight: black
  text-size: 3rem
  line-height: tight
  letter-spacing: wide
  text-align: start

text-size accepts xs, sm, md, lg, xl, 2xl, 3xl, 4xl, or a bounded px/rem size. Use shared tokens for ordinary hierarchy and explicit sizes for measured source typography that tokens cannot closely represent.

Style lists

Text leaves can select an application marker, disc, dash, or no marker, and can control list indentation and item gaps. The renderer preserves semantic list markup even when the visible marker changes.

Place controls and costs

Use control-density: compact and cost-density: compact only when space is constrained. Compact presentation retains selection, rolling, clearing, rank, validation, discount provenance, keyboard use, and accessible names. control-adornments: false removes the framework boundary when the authored surface already supplies it.

Tags are the exception to author typography: the Tags slot may be positioned, padded, and aligned, but its badge appearance remains User-owned.

Add images safely

image
  handle: region_map
  src: "maps/kanto.png"
  alt: "A map of Kanto with its major routes marked."

choice-layout
  handle: region_card

  inline
    text: description
    image
      target: region_map
      fit: contain
      size: xl

Asset paths are relative to assets/ and always use forward slashes. Give every meaningful image useful alternative text. Image leaves can control dimensions, fitting, aspect ratio, rounded corners, and edge fading within the schema bounds.

Validate and package

  1. Resolve every handle and asset reference.
  2. Fix syntax, schema, semantic, and distribution diagnostics.
  3. Preview Choices in unselected, selected, disabled, rolled, and repeated-rank states.
  4. Check narrow widths for overflow and readable order.
  5. Export through the Editor so definition and archive security validation runs.
  6. Import the resulting .jmp through package review before distribution.

Common errors

  • Using tabs or inconsistent indentation.
  • Placing a declaration in a context where it is not allowed.
  • Repeating a scalar field that is not repeatable.
  • Using display text where a handle reference is required.
  • Omitting a direct Choice or Choice Source from an explicit Section layout.
  • Referencing an asset outside assets/ or omitting alt text.
  • Expecting a single Choice Source to require a selection.
  • Using Tags as discount targets or attempting to author Tag appearance.
