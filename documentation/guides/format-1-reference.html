Special cases

These names and forms change meaning with their owner or rely on rules spanning several fields.

Special casedescription Metadata field or reserved text handle

Under jump, description is a quoted package-metadata field. A visible perk, item, form, or companion grant instead uses a nested text declaration whose handle must be exactly description.

Package metadata

jump
  description: "A concise package summary."

Visible grant text

grant
  kind: perk
  name: "Perfect Recall"
  text
    handle: description
    content: """
      You remember everything you study.
      """

Trait grants may own multiple text blocks and images through a trait layout; ordinary visible grants accept only the reserved description text.

Special caseIdentity properties gender, location, origin, species, age

Property grants write evaluated values for the current Chain entry. origin, species, location, and gender are strings; age is an integer. Omit value to copy the owning control only when its selection type is compatible. 

choice
  handle: starting_location
  name: "Starting Location"
  selection: select
  option: "The Capital"
  option: "The Frontier"
  grant
    kind: property
    handle: location
  • Copied gender requires a select Choice; copied age requires an integer Choice.
  • Copied origin, species, and location require a compatible string control.
  • continuity: previous | original applies only to a gender select with exactly one copied gender property grant.
  • Ordinary property values are entry-local; only engine identity continuity can seed gender or age from another entry.
Special casechoice context Definition versus Section placement

A top-level choice defines behavior and content. A choice nested under a Section only places that definition: its local handle is for layout targeting, while target points to the top-level definition.

Top-level definition

choice
  handle: skilled
  name: "Skilled"
  cost: 100
  grant: perk

Section placement

section
  handle: perks
  name: "Perks"
  choice
    handle: skilled_card
    target: skilled
Special caseScalar and block forms cost and grant

Scalar forms cover the common case. Use a block when you need another resource, per-unit cost, an explicit grant kind, names, Tags, ownership, quantities, or properties.

Scalar

cost: 100
grant: perk

Block

cost
  resource: tokens
  amount: 2
  mode: each
grant
  kind: item
  name: "Supply Crate"
  measure: quantity
Special caseConditional fields name, alt, content, option

Conditional variants follow their base field. The first matching expression wins in source order; the base value is the fallback when none match. Only declared boolean, integer, and string properties participate—there are no function calls, arithmetic, or coercion. 

name: "Traveler"
name when gender = "female":
  "Traveling Heroine"
name when gender = "male":
  "Traveling Hero"
Ownership boundaryTags and semantic slots Meaning versus presentation

Authors provide Tag strings and decide where the tags slot appears. The active User Tag profile always owns badge colors, borders, shape, typography, hierarchy, and animation. Cost badges are separate semantic elements and may use authored Cost-slot presentation.

Layout places semantic fields; it does not replace application controls or turn Tags into authored decoration.
