Living agent playbook

PDF-to-.jmp Conversion Guide

A decision-oriented workflow for reproducing the content, mechanics, artwork, color, and composition of an existing Jump without hiding what Format 1 cannot express.

Status: reference workflow established. The supplied source is authoritative, semantic and visual fidelity are separate hard gates, and every approximation must be explicit and traceable. Apply the companion visual-fidelity protocol to every conversion.

Conversion contract

A complete conversion delivers an editable project, a validated .jmp, extracted graphical assets, and a ledger connecting every source block to its representation. It is not complete merely because the archive imports.

  • Content fidelity: every heading, instruction, option, cost, award, description, and outcome is transcribed or deliberately marked uncertain.
  • Semantic fidelity: selections, costs, grants, properties, rolls, quantities, and ownership behave like the source wherever the format supports them.
  • Interaction fidelity: controls, roll affordances, cost badges, and clearing behavior remain understandable and reachable.
  • Visual fidelity: measured source silhouettes, major bounds, artwork, palette, hierarchy, density, and column rhythm pass an equal-width comparison or are explicitly marked blocked.
  • Traceability: unsupported behavior is named in prose and the ledger instead of being approximated invisibly.

Working-area structure

Conversion inputs and copyrighted source assets belong in an ignored scratch tree. Only reusable process documentation and gap decisions belong in the repository.

scratch/conversion-name/
  source/                 # authoritative PDF and supplied references
  extracted/pages/        # lossless page renders used for comparison
  extracted/assets/       # reusable crops with source coordinates
  project/
    jump.jdef
    choices.jdef
    layout.jdef
    assets/
  conversion-ledger.json
  converted-jump.jmp
  extract_pdf.py
  build.mjs

Never place the source PDF inside a .jmp. The archive accepts definition files and validated graphical assets only, and its limits and path rules remain a security boundary rather than a conversion inconvenience.

Phase 1: establish source truth

  1. Record the exact supplied filename, page count, page dimensions, visible title, author, edition, and whether a selectable text layer exists.
  2. Hash or retain the original bytes unchanged. A web copy may clarify text but must not silently replace the supplied edition.
  3. Render every page losslessly. For an image-only PDF, inspect the embedded image streams before introducing resampling.
  4. Transcribe once from enlarged renders and a second time while comparing each block directly with its page.
  5. Mark each ledger entry verified, uncertain, or externally-corroborated. Never use “verified” for a guess.

Secondary sources are evidence only. Record the source and the exact uncertainty they resolved; retain the PDF wording when sources disagree.

Inventory source concepts before writing declarations. Separate rules prose from actionable controls, and separate a thing's acquisition from its presentation.

Traits are the user-visible catchall for Jump-local circumstances. They render in the current Jump evaluation but are intentionally excluded from accumulated perk and item records. Do not convert a temporary biography, legal status, local curse, or insertion condition into a durable perk merely to make it visible.

Phase 3: choose stable authoring identities

  • Generate lower-snake-case handles from semantic names, then resolve collisions deliberately. A renamed display label must not force a handle change.
  • Use one package-wide group label for true shared membership. Do not use groups as layout columns.
  • Use direct placement handles when individually selectable cards need an authored grid.
  • Give companions and forms explicit stable handles before authoring targeted perks, resources, or ownership.
  • Keep source order unless the source itself states another ordering rule.

Phase 4: assign tags

Tags describe searchable effects. They do not encode mechanics.

  • Prefer one to three concrete built-in tags such as survival, repair, telekinesis, communications, or wealth.
  • Add a narrow setting tag such as pokemon only when it materially improves search.
  • Put shared tags on the Choice so ordinary grants inherit them. Put tags on a block grant when one Choice creates records with different meanings.
  • Do not tag a cost, discount, prerequisite, rarity, source page, section name, or unsupported rule.
  • Avoid redundant perk, item, and companion tags when record kind already communicates the distinction.

The application's canonicalization and user-owned tag relationships remain authoritative. A converter must not invent author-controlled hierarchy or badge styling.

Phase 5: extract and place images

Images preserve irreducible artwork, not authoring work. Before creating any crop that contains meaningful text, cost, rules, borders, or card composition, complete a semantic expressibility audit against the available section and choice layout nodes.

  1. Retain lossless full-page renders for verification.
  2. Crop only coherent graphical units that cannot reasonably be authored: logos, maps, individual sprites, character art, and textures. Record each crop's page and pixel bounds.
  3. Rebuild labels, descriptions, rules, costs, separators, backgrounds, and card structure with live Text, Slot, Rule, Stack, Inline, Wrap, and Grid nodes wherever those primitives can express them.
  4. Split mixed source strips into artwork-only crops and live text. For example, crop the six Starting Kit sprites separately and author their labels and descriptions in a six-column grid.
  5. Remove neither attribution nor meaningful labels when the crop depends on them for interpretation.
  6. Use PNG for source raster art unless a supported lossless format provides a material size benefit. Do not trace source raster art into invented SVG.
  7. Provide concise semantic alternative text. Decorative layout backgrounds must still originate from a validated Image block, but are not announced twice.
  8. Check per-image, package-pixel, expanded-byte, and compression-ratio limits before polishing layouts.

Phase 6: reproduce layout and color

First create the machine-readable visual specification required by the visual-fidelity protocol. Measure aspect ratios, major bounds, typography hierarchy, art anchoring, gaps, rules, and occupied-to-empty-area ratio before choosing layouts. Then sample exact source colors and map them to semantic appearance roles. A page's color is not automatically a safe control or focus color; contrast diagnostics must remain clean.

  • Cluster repeated source cards into measured archetypes, then use section layouts for major hierarchy and choice layouts for the repeated anatomy.
  • Match silhouette and major bounds before hierarchy and styling. Do not substitute a conventional name/art/prose stack when the source is a horizontal strip or asymmetrical display composition.
  • Place cost and action controls at the source's natural action edge. Re-measure after adding controls because an otherwise correct card can fail when a control rail changes its height.
  • Live semantic name, cost, artwork, prose, rules, and controls are the primary presentation. A text-bearing facsimile is a separate fallback mode, never a substitute for attempting the semantic layout.
  • Use responsive two- or three-column grids only when individual direct choices occupy the cells. An expand is a single layout node and does not expose authored columns for its child cards.
  • Use rules, backgrounds, borders, spacing, text-size tokens, and image sizing before declaring a gap, then cite the exact schema or renderer constraint for anything marked blocked.

Presentation variants

When exact source pixels are useful, preserve two explicit outputs rather than blending their claims:

  • Semantic mode: live reflowable text, live costs and controls, artwork-only crops, and the closest declarative layout.
  • Facsimile mode: measured source panels for pixel reference, backed by the same semantic Choice data and clearly marked accessibility and dynamic-state limitations.

Format 1 currently has no package-level presentation profiles or user preference for switching between these modes. Until that capability exists, retain separate scratch builds and make semantic mode the conversion's primary acceptance target.

Unsupported-mechanics policy

Never counterfeit a source rule. Use the nearest valid control, preserve source prose and base values, and attach a stable gap ID.

Conversion ledger contract

The ledger is working data, not a second Jump definition. Each entry records a stable ID, source page and pixel bounds, transcription status, target file and handles, semantic kinds, tags, fidelity result, and gap IDs. Its top level records source authority, page geometry, policy, gap definitions, and verification results.

{
  "id": "choice:example",
  "source": { "page": 4, "bounds": [0, 255, 1920, 300] },
  "transcription": { "status": "verified", "authority": "supplied-pdf" },
  "target": { "file": "choices.jdef", "handles": ["example"] },
  "tags": ["survival"],
  "fidelity": "transparent-approximation",
  "gaps": ["GAP-001"]
}

Verification and acceptance

  1. Canonicalize using the distribution profile and the exact asset path set. Resolve every error and warning.
  2. Build the archive and inspect it through the secure package import service. Require ready, not a partially reviewed hand-built ZIP.
  3. Import through the real Editor UI and inspect every section at desktop and narrow viewport widths.
  4. Exercise every distinct mechanic: manual and rolled selection, continuity, single and multi groups, text/select/integer controls, flat and repeated costs, awards, properties, every grant kind, and ownership targets.
  5. Capture rendered evidence after images settle. Compare every archetype to its source at equal content width.
  6. Require aspect ratio and major bounds within 10%, matching direction, art anchoring, casing, hierarchy, line count, exact palette, and no large unmatched whitespace. Controls must not silently displace the composition.
  7. List the five largest perceptual differences, fix every authoring defect, and label each residual difference blocked with the exact missing capability. When an artifact disagrees with expected behavior, trust the artifact and continue.
  8. Update ledger verification only after the exact path passes. Leave known gaps open and named.

Handoff checklist

  • Original source remains unchanged and ignored.
  • Every source block has a ledger entry and a second transcription pass.
  • Every referenced image exists, validates, and has appropriate alternative text.
  • Definition diagnostics and secure archive diagnostics are empty.
  • The built .jmp imports and exercises successfully.
  • Equal-width visual evidence covers every source page and every card archetype, with an explicit pass, fail, or blocked result.
  • Known gaps appear in both the ledger and a persistent audit when they reveal reusable format limitations.
  • No scratch source, extracted asset, or converted archive enters the repository commit.
