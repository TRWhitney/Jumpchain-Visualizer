Required conversion gate

Visual Fidelity for Autonomous PDF-to-.jmp Conversion

The instructions and evidence an agent needs to reproduce a source composition without a human having to notice that the result is visibly wrong.

Decision: visual similarity is a completion requirement, not a preference. A valid archive with accurate prose is still a failed conversion when the rendered composition does not resemble the source.

Why the first Pokémon pass failed

The first pass treated a Region as a generic responsive card. The source treated it as a tightly measured horizontal display strip. That was an implementation and review failure before it was a format limitation.

Required source measurements

Do not author a layout until the source has a machine-readable visual specification. Measure the following in source pixels and normalized percentages so the same specification works at another render width:

  • page and panel aspect ratios;
  • major bounding boxes for title, prose, art, price, separators, and intentional empty space;
  • layout direction, column count, unequal column proportions, row spans, and overlap;
  • art dimensions, crop, alignment, and distance from each edge;
  • text casing, alignment, line count, relative size, weight, condensation, and line spacing;
  • palette sampled from the source rather than estimated;
  • border width, gutters, card gaps, corner geometry, and occupied-to-empty-area ratio;
  • the natural position and footprint of interactive controls that must be added.

Cluster repeated measurements into named visual archetypes—such as horizontal region strip, two-column skill card, or charcoal flaw row—and define one reusable layout per archetype. Generic cards are prohibited until this clustering is complete.

Implementation order

  1. Reconstruct the source silhouette. Match aspect ratio, direction, column proportions, and art anchoring before styling text.
  2. Reconstruct hierarchy. Match display-name dominance, casing, line breaks, price emphasis, and description density.
  3. Apply exact visual tokens. Use sampled colors, measured rules, square or rounded geometry, and measured gaps.
  4. Add interaction without redesigning the source. Put controls at an existing action edge, in an existing reserved region, or in the smallest clearly additive rail. Re-run the geometry checks after controls are present.
  5. Audit semantic expressibility before any text-bearing crop. Decompose the panel into Stack, Inline, Wrap, Grid, Rule, Text, Slot, Input, and artwork-only Image nodes. Record which exact primitive blocks each remaining difference.
  6. Keep facsimile output as a separate mode. A cropped source panel may preserve exact typography and composition for comparison, but must not replace the primary semantic attempt. Record its accessibility, reflow, rights, and dynamic-state losses.

A facsimile is a transparent alternate presentation, not evidence that the format can semantically express the design. The underlying Choice must retain verified name, description, cost, tags, and grants. The crop needs meaningful alternative text, and the ledger must identify its source coordinates. The semantic package must not reference the text-bearing crop.

Hard visual acceptance gate

Compare source and rendered artifacts at the same content width. Each archetype receives an explicit pass, fail, or blocked result; “recognizable” is not a result.

  • overall and card aspect ratios differ by no more than 10% unless a named control rail explains the additional dimension;
  • major title, prose, artwork, price, and rule bounds are within 10% of their source positions and dimensions;
  • layout direction, art edge anchoring, casing, dominant type hierarchy, and description line count match;
  • the exact sampled palette is used;
  • no large unmatched whitespace appears;
  • controls do not displace, cover, or reorder source content without a recorded gap;
  • the side-by-side pair reads as the same composition at a glance.

Thresholds are necessary but not sufficient. A renderer can satisfy an aspect ratio while moving the map, shrinking the name, or losing the hierarchy. The final glance comparison remains mandatory.

Iteration and evidence loop

  1. Capture the source panel and rendered panel at equal width.
  2. List the five largest visible differences, ordered by perceptual impact.
  3. Classify each difference as an authoring defect or a demonstrated format gap.
  4. Fix authoring defects and capture again. Never stop merely because a test is green.
  5. For a format gap, cite the exact schema or renderer constraint and preserve a minimal reproducer.
  6. Retain source crops, screenshots, measured geometry, and the pass/fail/blocked record in ignored scratch evidence.

The screenshot is the authority for a visual claim. If implementation reasoning says the layout should match but the screenshot does not, trust the screenshot and continue.

Independent visual critic

When subagents are available, assign a critic that did not author the conversion. Give it only the source crop, rendered crop, measurement specification, and acceptance rubric. Ask it to return:

  • pass, fail, or blocked for each acceptance check;
  • the five largest perceptual differences;
  • whether each difference is actually prevented by Format 1;
  • the next highest-value change, without editing the project.

The primary agent remains responsible for checking the critic's claims against the schema and for iterating. A critic does not replace direct visual inspection.

Blocked versus complete

If the requested fidelity requires capabilities outside the authorized task, stop calling the conversion complete. Report the exact blocked property—for example, “controls cannot overlay an image or reserve absolute coordinates”—and present the best safe fallback. The developer must be able to distinguish:

  • semantic match: the renderer recreates the source with live text and layouts;
  • facsimile match: a separately labeled presentation profile preserves source pixels while live controls remain additive;
  • approximation: the composition differs but preserves selected visual tokens;
  • blocked: an acceptance criterion cannot be met without a format or renderer change.

Reusable agent prompt

Treat visual similarity as a completion requirement.

Before authoring:
1. Render every source page losslessly.
2. Produce a machine-readable visual specification with page/card bounds,
   normalized proportions, aspect ratios, typography hierarchy, palette,
   art anchoring, borders, gaps, whitespace ratio, and control locations.
3. Cluster repeated cards into visual archetypes. Do not use a generic card
   layout until the archetypes are identified.

During authoring:
4. Match silhouette and major bounds first, hierarchy second, styling third.
5. Keep interactive controls additive and at a natural source action edge.
6. Keep semantic text, costs, tags, grants, rules, and card structure live.
   Crop only irreducible artwork in the primary presentation.
7. If useful, build a separately labeled facsimile presentation after the
   semantic attempt; never use it to bypass expressible layout work.

Verification:
8. Capture source and render at equal width for every archetype.
9. Require aspect ratio and major bounds within 10%, matching layout direction,
   art anchoring, casing, hierarchy, line count, palette, and no unmatched
   whitespace.
10. List and fix the five largest visible differences. Repeat until each check
   passes or is demonstrably blocked by the format.
11. If blocked, cite the exact missing capability and do not label the visual
    conversion complete. Preserve screenshots and measurements as evidence.

Use an independent visual critic when available. Trust the rendered artifact
over implementation intent.

Script and future skill boundary

A reusable conversion skill should package deterministic scripts for page rendering, crop generation, color sampling, geometry extraction, contact sheets, equal-width screenshots, aspect/bounds checks, pixel or perceptual comparisons, ledger generation, archive building, and secure import verification. The skill instructions should own the decision gates; scripts should collect evidence and perform mechanical work rather than decide that a composition “looks close.”
