Living preference registry

Settings design

The authoritative list of configurable application behavior, including defaults, allowed values, scope, persistence, and decision status.

Current state: appearance, accent color, motion, Editor save mode, Chain Tracker behavior, notification presentation, keybinding overrides, and the user tag profile are confirmed. Session logs are available as a Developer utility rather than persisted settings.

Purpose

This page prevents preferences from being invented ad hoc during feature implementation. A behavior belongs here only when users have a meaningful reason to choose between supported alternatives. Document semantics, package content, and author presentation choices belong in the Jump package or markup—not in application settings.

Settings Principles

  • Defaults should serve most users without requiring setup.
  • Settings solve genuine preference, accessibility, environment, or compatibility needs; they do not replace a clear product decision.
  • Application settings are user-local and must not alter the portability or meaning of a Jump package.
  • Each setting has a stable key, explicit default, bounded value type, scope, validation rule, and migration story.
  • Unsupported or invalid stored values fall back safely to the documented default and produce a recoverable diagnostic.
  • Security-sensitive values and filesystem permissions are not ordinary settings and must not be stored in this registry as plain preference data.

Presentation and Routing

Settings uses the agreed route-backed overlay. Opening it from Home or a workspace pushes /settings, preserves the prior route underneath as inert content, and restores that route on Close, Escape, or Back. Opening /settings directly renders the same content as a full page.

The initial surface includes persistent categories, global setting search, visible defaults, and a per-setting Reset action. The Settings frame keeps one compact, stable height across categories; each category and complex editor scrolls inside its own content region instead of resizing the dialog. Changes normally apply immediately; settings that cannot apply safely without restart must say so before the user changes them.

Language is the first setting in General. Its native dropdown applies immediately and uses each pack folder name as that language's self-name. English appears first and remains the invalid-value fallback. See Localization Resources.

Settings Search

Search covers every category and matches visible labels, stable setting keys, descriptions, allowed values, and maintained aliases. Results identify their owning category. Selecting a result clears the query, opens that category, and focuses the setting. Clearing an unfinished search restores the category that was selected before searching.

Confirmed Setting Amendments

These settings were accepted after the initial registry and are implemented in the same persisted Settings model.

Allow Duplicate Jumps in a Chain

KeyDefaultAllowed valuesScopeReason
chain.allowDuplicateJumpsfalsetrue, falseChain TrackerAllows the Chain Tracker’s Add action to create another entry from the same exact installed Jump package while preserving independent choices, rolls, and chronology for every entry.

This setting is separate from chain.allowMultiplePackageVersions, which permits a different installed version of the same logical package but still does not duplicate an exact version. With duplicate Jumps disabled, a library package already represented by that exact version uses Open chain entity. With the setting enabled, its add action reads Add to chain again (xN), where N is the number of exact-package entries that will exist after the action. Adding the first instance continues to read Add to chain.

The setting gates only a deliberate interactive Add action. Turning it off never removes, merges, invalidates, or warns about duplicate entries already present, and chain import preserves duplicates without consulting the setting.

Aggregate Similar Perks and Items

chain.aggregateSimilarInventory defaults to true. When enabled, Inventory combines records only when the owner, record kind, resolved display name, and rank match. Perks never combine with items, different owners and forms remain isolated, and different ranks remain distinct. Package identity, source Jump, and effective grant handle do not participate in similarity, allowing independently authored acquisitions from different packages to share one xN aggregate.

The aggregate carries the stable union of every constituent tag. Its detail overlay lists each acquisition’s Jump, resolved description, and contributed quantity independently. Four or more acquisition rows use a bounded, keyboard-focusable scroll region so long source labels and descriptions cannot grow the dialog without limit. Disabling the setting restores strict aggregation, which combines only repeated instances of the same effective grant from the same exact package.

The user-owned tag profile is now confirmed and represented by the Tags page below. Its detailed relationship, chart, badge, and transfer rules remain in Tag System Design. Jump authors still provide only free-text tag strings.

Accent Color Safety

appearance.accentColor stores only a normalized six-digit sRGB hex value. The raw base color may be used for decorative swatches, but the application derives separate accessible tokens for text, focus indicators, borders, filled controls, and subtle surfaces in Light and Dark themes. Those tokens apply across the application shell, saved-chain hub, Chain Tracker, radar interface, supplement frame, Settings, and tag-profile tools. Secondary action outlines, dashed discovery actions, interactive hover fills, selected-card borders, and the new-chain callout use the derived border and translucent-surface tokens; structural dividers and ordinary input boundaries remain neutral. Continuous color-picker input is visually published at a bounded interactive rate and durably coalesced after the interaction, preserving live feedback without an unbounded render or event stream. Derived tokens must retain the selected hue as closely as possible while meeting the applicable contrast requirement. Raw setting text must never be interpolated directly into styles.

Light mode’s semantic palette is #f6f5f1 canvas, #ffffff elevated surface, #f3f1eb secondary surface, #171717 primary text, #343430 body text, #686861 muted text, #cbc8bf structural border, and #aaa79e control border. Text targets WCAG 2.x contrast of at least 4.5:1 and meaningful focus/control boundaries target at least 3:1. Delete actions use separate deep-red light-theme text and border tokens. Developer Logs use the same elevated surfaces, with darker semantic Info and Warn badge colors in Light mode. Tag-profile Import, Export, and Reset actions use neutral secondary controls; Settings rows and popup options must retain light secondary surfaces while hovered or keyboard-focused. Selecting Light also sets the root native color-scheme to light; selecting Dark preserves the existing dark palette and native scheme without reinterpreting it through light tokens.

Transparent tag badges adapt their rendered text—not their stored profile value—to the surface beneath them. A configured light text color is darkened only far enough to remain readable across standard Light surfaces, and a configured dark text color is similarly lightened across Dark surfaces. The canonical badge renderer owns this behavior so the Tags preview and every application badge remain consistent.

Notification Projection

The Settings modal remembers its last-open category for the current application session. Toast preferences control the user-facing projection of registered events described in Logging Design. Disabling a toast class does not suppress its session log entry, diagnostic, or completed state transition. Transient actions, including Undo for a chain reorder or removal, render in that same notification stack and expire or are discarded with their notification. Input-driven candidates are debounced for 500 ms and repeated matching events update one toast rather than creating a stream of duplicates. A choice rejected for causing a negative balance uses the danger treatment: a red edge, X icon, and the message “Choice rejected, negative balance”.

Interactive Settings Surface

The category navigation, accent picker, search, notification preview, tag-profile editor, and Developer session-log viewer are interactive. Changing the accent updates the complete application while preserving the current gold as the Reset default. Confirmation-state labels are documentation metadata and do not appear as badges in the application. The Tags page uses the accepted editor from Tag System Design.

Tag Profile Scope and Transfer

  • The Tags page edits tags.profile; it does not add tag relationships or presentation fields to Jump markup.
  • The twelve Primary Tags and the expanded non-primary Built-In Tags catalog are always present in separate collapsible sections. Primary Tags remain fixed radar axes; non-primary built-ins retain protected identities while allowing parent, alias, and presentation changes.
  • Refresh acquired tags explicitly scans installed Jump package tag metadata and adds only normalized strings not already represented by a canonical name or alias. Detected entries appear under Acquired Tags as Installed jump; manually entered entries share that section as Custom.
  • Parents, reciprocal alias links, and badge overrides are user-local. Changing them affects search expansion and rendering without rewriting imported content.
  • The tag profile has dedicated versioned JSON import and export because it is intentionally shareable. Acquired records and Jump source are never included.
  • Per-tag Reset restores built-in defaults or returns a custom tag to parent-derived presentation, depending on the selected tag’s source.
  • Manual and imported profile-only tags may be deleted. Deletion automatically removes their alias links and reparents direct children; built-ins and tags discovered from installed Jumps remain protected.

Developer Package Size Limits

Developer → Overview contains an opt-in Package size limits section. Safe effective defaults are 64 MiB archive, 2 MiB definition, 16 MiB asset, and 96 MiB expanded. Enabling overrides first displays Increase package limits at your own risk; cancellation leaves defaults effective. Disabling preserves entered values but restores safe effective values, while Reset disables and restores all defaults.

Values are whole MiB, definition and asset limits cannot exceed the expanded limit, and absolute ceilings are 512/16/256/1024 MiB respectively. Invalid persisted or edited values fall back safely and never reach archive adapters. Active overrides appear with an At your own risk warning in every import review and export confirmation, and affect Editor import/export, desktop folder loading, and Chain Tracker installation. They never disable structural or malicious-file protections.

Developer Editor Folder Action

developer.showOpenProjectFolder is off by default. Enabling it exposes the existing Open Project Folder action on the Editor hub; it does not weaken desktop-only capability detection or change folder security, persistence, watching, conflict, or recovery behavior.

Persistence and Migration

  • Settings persist independently from Jump packages and Chain records.
  • The persisted object carries schema version 2 and is migrated before use; version 1 receives language.tag = "en".
  • Missing keys receive current defaults; migrations do not rewrite unrelated preferences.
  • A Reset action restores one setting, one category, or the complete registry without deleting projects or chains.
  • General preference import/export remains deferred. The tag profile is the explicit exception and has its own versioned JSON transfer format.
  • Developer session logs and the debug-capture toggle never persist; every application launch starts with an empty log and debug capture disabled.
